## 5.1 从 TS 的 class 到 Go 的 struct

TS 用 `class` 把数据和方法包在一起；Go 没有 `class`，而是把「数据」和「方法」分开声明：
```go
type User struct {
    Name string
    Age  int
}

func (u User) Greet() string {
    return "我是 " + u.Name
}
```
对应关系：

| TypeScript | Go |
|------------|-----|
| `class` | `struct` |
| 字段 | 结构体字段 |
| 方法 | 带接收者的函数 |
| `this` | 接收者 `u` |
| `constructor` | 惯例函数 `NewUser(...)` |
| `extends` | 嵌入（embedding）+ 组合 |
| `public` / `private` | 首字母大小写 |

关键差异：

- Go 的方法必须定义在**同一个包**里，不能给别的包的类型加方法；
- Go 没有继承，嵌入只是组合，不产生子类型关系；
- Go 没有构造函数语法，用 `NewXxx` 惯例；
- Go 的字段导出由首字母决定，没有 `public/private` 关键字。

## 5.2 定义结构体、字段导出与零值

### 5.2.1 基本定义
```go
type User struct {
    ID   int
    Name string
    Age  int
}
```
字段名在结构体内必须唯一。字段顺序有影响：

- 按位置初始化时依赖顺序；
- 内存布局依赖顺序（5.11 节）。

### 5.2.2 字段导出规则

首字母大写才能被其他包访问：
```go
package model

type User struct {
    Name string // 导出，其他包可读写
    age  int    // 未导出，只有 model 包内能访问
}
```
其他包：
```go
u := model.User{Name: "张三"} // 可以
fmt.Println(u.Name)           // 张三
// u.age = 18                  // 编译错误：age 未导出
```
同一包内不受限制。导出规则同样适用于结构体类型名、方法名、字段名。

> 为什么重要：`encoding/json`、GORM、Gin 的绑定都只能处理**导出字段**。字段写成小写，编译不会报错，但 JSON 里没有它、数据库里也没有它，这是非常常见的 silent bug。

### 5.2.3 零值
```go
var u User
fmt.Printf("%+v\n", u) // {ID:0 Name: Age:0}
```
每个字段都是其类型的零值。Go 鼓励「零值可用」的设计，例如 `bytes.Buffer`、`sync.Mutex` 声明后即可使用。设计自己的结构体时，也尽量让零值有合理含义。

## 5.3 初始化

### 5.3.1 四种常见方式
```go
// 1. 按字段名（推荐）
u1 := User{ID: 1, Name: "张三", Age: 25}

// 2. 按位置（不推荐：加字段就编译失败）
u2 := User{1, "张三", 25}
fmt.Println(u2.Name) // 张三

// 3. 先声明零值，再赋值
var u3 User
u3.Name = "张三"
fmt.Println(u3.Name) // 张三

// 4. 指针 + 字面量
u4 := &User{Name: "张三"}
```
按位置初始化必须列出**所有**字段，且顺序一致；新增字段会让所有位置字面量编译失败，所以实际项目几乎都用字段名。

`fmt` 的输出差异：
```go
fmt.Println(u1)        // {1 张三 25}
fmt.Printf("%+v\n", u1) // {ID:1 Name:张三 Age:25}
fmt.Printf("%#v\n", u1) // main.User{ID:1, Name:"张三", Age:25}
fmt.Println(u4)         // &{0 张三 0}
```
调试结构体时 `%+v` 最常用；`%#v` 会带上类型名，适合排查类型问题。

### 5.3.2 嵌套结构体
```go
type Address struct {
    City string
}

type User struct {
    Name string
    Addr Address
}

u := User{
    Name: "张三",
    Addr: Address{City: "北京"},
}
fmt.Println(u.Addr.City) // 北京
```
嵌套字段必须显式初始化，否则是对应结构体的零值。嵌套字面量内层类型可以省略：`Addr: {City: "北京"}`，但初学阶段写全更清楚。

### 5.3.3 匿名结构体

不需要复用类型时，可以直接定义：
```go
point := struct {
    X, Y int
}{X: 1, Y: 2}

fmt.Println(point) // {1 2}
```
匿名结构体常用于测试表格、临时 JSON 响应，例如 ``struct { Code int `json:"code"`; Msg string `json:"msg"` }{Code: 0, Msg: "ok"}``。

### 5.3.4 `new(T)` 与 `&T{}`
```go
p1 := new(User)   // *User，所有字段零值
p2 := &User{}     // *User，所有字段零值
p3 := &User{Name: "张三"}

fmt.Println(p1) // &{0  0}
fmt.Println(p2) // &{0  0}
fmt.Println(p3) // &{0 张三 0}
```
- `new(T)` 只接收类型，返回 `*T`，无法初始化字段；
- `&T{}` 是复合字面量取地址，可以顺便初始化；
- 结构体场景优先 `&T{}`，可读性更好；
- `new` 对 `int`、`bool` 等也适用，例如 `p := new(int)` 得到指向 0 的 `*int`。

注意 `new` 和 `make` 不同：`make` 只用于 slice、map、chan，返回初始化好的值；`new` 返回指针。

### 5.3.5 结构体的可比较性

所有字段都可比较时，结构体可以用 `==`、`!=`：
```go
type Point struct{ X, Y int }

fmt.Println(Point{1, 2} == Point{1, 2}) // true
```
含 slice、map、func 字段的结构体不可比较：
```go
type Bad struct {
    Tags []string
}

// Bad{} == Bad{} // 编译错误：struct containing []string cannot be compared
```
需要比较内容时，自己写比较函数，或用 `reflect.DeepEqual`（测试里常见，业务热路径慎用）。

## 5.4 方法：值接收者与指针接收者

### 5.4.1 定义方法

方法就是带接收者的函数，接收者写在 `func` 和函数名之间：
```go
type Rectangle struct {
    Width, Height float64
}

func (r Rectangle) Area() float64 {
    return r.Width * r.Height
}

func (r *Rectangle) Scale(f float64) {
    r.Width *= f
    r.Height *= f
}
```
```go
r := Rectangle{Width: 3, Height: 4}

fmt.Println(r.Area()) // 12
r.Scale(2)
fmt.Println(r.Area()) // 48
```
### 5.4.2 值接收者 vs 指针接收者

值接收者拿到的是副本：
```go
func (r Rectangle) SetWidth(w float64) {
    r.Width = w // 只改副本
}

r := Rectangle{Width: 3, Height: 4}
r.SetWidth(10)
fmt.Println(r.Width) // 3
```
指针接收者拿到的是原对象：
```go
func (r *Rectangle) SetWidth(w float64) {
    r.Width = w
}

r.SetWidth(10) // 自动取地址，等价于 (&r).SetWidth(10)
fmt.Println(r.Width) // 10
```
| 接收者 | 函数内拿到 | 修改是否影响调用方 | 适用场景 |
|--------|------------|--------------------|----------|
| `func (r T)` | 副本 | 否 | 只读、小对象、值语义 |
| `func (r *T)` | 指针 | 是 | 需要修改、大对象、含锁/共享状态 |

### 5.4.3 自动取地址与自动解引用

Go 会自动处理：
```go
r := Rectangle{Width: 3}

r.Scale(2)        // 自动变成 (&r).Scale(2)
p := &r
fmt.Println(p.Area()) // 自动变成 (*p).Area()
```
但**不可寻址的值**不能调用指针接收者方法：
```go
// Rectangle{Width: 3}.Scale(2) // 编译错误：cannot call pointer method on Rectangle literal
```
因为字面量没有稳定地址，无法自动取 `&`。

### 5.4.4 方法与函数的区别
```go
func area(r Rectangle) float64 { return r.Width * r.Height } // 函数
func (r Rectangle) Area() float64 { return r.Width * r.Height } // 方法
```
- 方法绑定了一个接收者类型，可以像 `r.Area()` 这样调用；
- 方法可以形成方法值 `f := r.Area`，此时 `f` 的类型是 `func() float64`，接收者已绑定；
- 方法表达式 `Rectangle.Area` 的类型是 `func(Rectangle) float64`，接收者作为第一个参数；
- 函数更通用，方法更适合表达「这个类型能做什么」。

### 5.4.5 方法的限制

**不能重载**：同一类型不能有两个同名方法，即使参数不同。

**字段和方法不能同名**：
```go
type T struct{ Name string }
// func (t T) Name() string { return "" } // 编译错误：field and method with the same name Name
```
**只能给本包定义的类型加方法**：
```go
// func (t time.Time) Foo() {} // 编译错误：cannot define new methods on non-local type time.Time
```
想扩展外部类型，用包装结构体或函数：
```go
type MyTime struct {
    time.Time
}

func (t MyTime) Foo() {}
```

## 5.5 方法集

### 5.5.1 规则

| 类型 | 方法集包含 |
|------|------------|
| `T` | 所有值接收者方法 |
| `*T` | 值接收者方法 + 指针接收者方法 |

也就是说：

- 值类型 `T` 只能「看到」值接收者方法；
- 指针类型 `*T` 能看到全部方法。

### 5.5.2 对接口实现的影响
```go
type Speaker interface {
    Speak() string
}

type Dog struct{ Name string }
func (d Dog) Speak() string { return d.Name + "：汪" }

type Cat struct{ Name string }
func (c *Cat) Speak() string { return c.Name + "：喵" }

func main() {
    var s1 Speaker = Dog{Name: "旺财"}  // 值接收者：Dog 和 *Dog 都实现
    var s2 Speaker = &Cat{Name: "咪咪"} // 指针接收者：只有 *Cat 实现

    fmt.Println(s1.Speak()) // 旺财：汪
    fmt.Println(s2.Speak()) // 咪咪：喵

    // var s3 Speaker = Cat{Name: "咪咪"} // 编译错误：Cat does not implement Speaker
}
```
原因：`Cat` 的方法集里没有 `Speak`，只有 `*Cat` 有。

### 5.5.3 如何选择接收者

经验规则：

1. 需要修改接收者 → 指针；
2. 结构体较大（包含多个字段、数组、大结构体）→ 指针；
3. 含 `sync.Mutex` 等不可复制字段 → 必须指针；
4. 其他情况 → 值接收者，语义更简单；
5. **同一类型的方法尽量统一接收者**，不要一半值一半指针，否则方法集容易让人困惑。

> 把值存进接口时会发生拷贝。如果方法需要修改原对象，接收者必须是指针，且接口里存的也必须是指针。

## 5.6 嵌入与组合

### 5.6.1 匿名字段

嵌入是把一个类型作为字段，但不写字段名：
```go
type Base struct {
    ID int
}

func (b Base) Describe() string {
    return fmt.Sprintf("Base(%d)", b.ID)
}

type User struct {
    Base // 匿名字段，字段名就是 Base
    Name string
}

u := User{Base: Base{ID: 1}, Name: "张三"}

fmt.Println(u.ID)         // 1，字段提升
fmt.Println(u.Base.ID)    // 1，也可以显式访问
fmt.Println(u.Describe()) // Base(1)，方法提升
```
嵌入后：

- `Base` 的字段被「提升」到 `User`，可以直接 `u.ID`；
- `Base` 的方法也被提升，可以直接 `u.Describe()`；
- 字段名仍然是 `Base`，所以字面量要写 `Base: Base{...}`。

### 5.6.2 方法提升与覆盖
```go
func (u User) Describe() string {
    return "User:" + u.Name
}

fmt.Println(u.Describe())        // User:张三，外层优先
fmt.Println(u.Base.Describe())   // Base(1)，显式调用内层
```
外层定义同名方法会遮蔽内层方法。需要内层行为时，显式写 `u.Base.Describe()`。

### 5.6.3 同名冲突

两个嵌入类型有同名字段或方法时，选择会变得歧义：
```go
type A struct{ Name string }
type B struct{ Name string }

type C struct {
    A
    B
}

c := C{A: A{Name: "a"}, B: B{Name: "b"}}
fmt.Println(c.A.Name, c.B.Name) // a b

// fmt.Println(c.Name) // 编译错误：ambiguous selector c.Name
```
规则：

- 同深度同名 → 歧义，必须显式限定；
- 外层自己定义的字段/方法优先于提升的；
- 浅层优先于深层。

### 5.6.4 嵌入不是继承

这是最重要的一点。嵌入只是「把字段和方法放进来」，不会产生子类型关系，也没有动态派发。
```go
type Animal struct{}
func (Animal) Speak() string { return "..." }

type Dog struct{ Animal }
func (Dog) Speak() string { return "汪" }

d := Dog{}
fmt.Println(d.Speak())        // 汪
fmt.Println(d.Animal.Speak()) // ...

// var a Animal = d // 编译错误：Dog 不是 Animal
```
如果函数接收 `Animal`，不能传 `Dog`：
```go
func describe(a Animal) string { return a.Speak() }
// describe(d) // 编译错误
describe(d.Animal) // 可以，显式取出内层
```
这和 TS 的 `extends` 完全不同：

- TS 子类可以赋给父类类型，方法调用是动态派发；
- Go 嵌入没有子类型关系，方法调用在编译期确定；
- 想实现多态，用接口（第 07 章）。

### 5.6.5 嵌入指针与嵌入接口

嵌入指针：
```go
type Audit struct {
    CreatedBy string
}

type Order struct {
    *Audit
    ID int
}

o := Order{Audit: &Audit{CreatedBy: "admin"}, ID: 1}
fmt.Println(o.CreatedBy) // admin，自动解引用
```
如果嵌入指针是 nil，访问提升字段会 panic（`nil pointer dereference`）。

嵌入接口（第 07 章展开）时，接口类型作为匿名字段，方法被提升；`Service` 的 `Log` 实际调用 `Logger` 字段，字段为 nil 时调用会 panic。

### 5.6.6 组合优于继承

嵌入适合「复用字段/方法」，不适合模拟继承层次。更推荐显式命名字段，例如 `type UserService struct { repo UserRepository }`，关系更清楚。

判断标准：

- 想表达「是一个」→ 用接口；
- 想表达「有一个」→ 用命名字段；
- 想复用一组字段/方法且不介意提升 → 用嵌入。

## 5.7 结构体标签

### 5.7.1 语法

标签写在字段类型后面的反引号里：
```go
type User struct {
    ID       uint   `json:"id" gorm:"primaryKey"`
    Name     string `json:"name" gorm:"size:64;not null"`
    Email    string `json:"email,omitempty" gorm:"uniqueIndex;size:128"`
    Password string `json:"-" gorm:"size:255"`
    Age      int    `json:"age" gorm:"default:18"`
}
```
形式是 `key:"value"`，多个键用空格分隔。标签本身是一个字符串，编译期不校验内容。

### 5.7.2 `json` 标签

- `json:"name"`：JSON 字段名；
- `json:"name,omitempty"`：零值时省略；
- `json:"-"`：不参与 JSON 序列化；
- `json:",omitempty"`：保留字段名，只加选项；
- 选项用**逗号**分隔。
```go
type User struct {
    Name string `json:"name"`
    Age  int    `json:"age,omitempty"`
    Pass string `json:"-"`
}

b, _ := json.Marshal(User{Name: "张三"})
fmt.Println(string(b)) // {"name":"张三"}
```
### 5.7.3 `gorm` 标签

- `primaryKey`：主键；
- `column:user_name`：列名；
- `type:varchar(64)`：列类型；
- `size:64`：长度；
- `not null`：非空；
- `default:18`：默认值；
- `uniqueIndex` / `index`：索引；
- `autoIncrement`：自增；
- `-`：忽略该字段；
- 选项用**分号**分隔。
```go
type User struct {
    ID    uint   `gorm:"primaryKey;autoIncrement"`
    Name  string `gorm:"column:user_name;size:64;not null"`
    Email string `gorm:"uniqueIndex;size:128"`
    Age   int    `gorm:"default:18"`
}
```
### 5.7.4 `form`、`binding`、`validate`
```go
type LoginRequest struct {
    Username string `form:"username" json:"username" binding:"required"`
    Password string `form:"password" json:"password" binding:"required,min=6"`
}

type GetUserRequest struct {
    ID uint `uri:"id" binding:"required,gt=0"`
}
```
`binding` 的选项用**逗号**分隔，底层是 go-playground/validator。常见规则：

| 标签 | 含义 |
|------|------|
| `required` | 必填 |
| `min=2` / `max=20` | 长度或数值范围 |
| `email` | 邮箱格式 |
| `gte=0` / `lte=120` | 大于等于 / 小于等于 |
| `oneof=admin user` | 枚举值 |
| `-` | 跳过校验 |

`validate` 标签是同一个 validator 库的直接用法，常见于非 Gin 项目，例如 ``Name string `validate:"required,min=2"` ``；它和 `binding` 只是标签键不同。

### 5.7.5 标签的常见坑

- **json 用逗号，gorm 用分号**，写反了不会报错，只会静默失效；
- 键名拼错（`jsom`、`grom`）不会报错；
- 未导出字段不会参与 JSON/GORM，即使写了标签；
- `json:"-"` 只影响 JSON，不影响 GORM；要让 GORM 忽略，写 `gorm:"-"`；
- 标签里不能出现反引号；
- 标签只是元数据，真正解析它的是库（`encoding/json`、GORM、Gin）。

## 5.8 反射够用版

反射解决一个问题：**程序运行时才知道类型和字段**。`encoding/json`、GORM、Gin 都靠它读标签、写字段。

### 5.8.1 `TypeOf` 与 `ValueOf`
```go
package main

import (
    "fmt"
    "reflect"
)

type User struct {
    ID    uint   `json:"id" gorm:"primaryKey"`
    Name  string `json:"name" gorm:"size:64;not null"`
    Email string `json:"email,omitempty" gorm:"uniqueIndex"`
}

func main() {
    t := reflect.TypeOf(User{})
    fmt.Println(t.Name())  // User
    fmt.Println(t.Kind())  // struct

    v := reflect.ValueOf(User{Name: "张三"})
    fmt.Println(v.Kind())                       // struct
    fmt.Println(v.FieldByName("Name").String()) // 张三
}
```
- `TypeOf` 返回类型信息；
- `ValueOf` 返回值信息；
- `Kind` 是底层种类：`struct`、`ptr`、`slice`、`map`、`int`、`string` 等；
- `Name` 是命名类型的名字，匿名类型返回空字符串。

`reflect.TypeOf(nil)` 返回 `nil`，直接调用方法会 panic，使用时要注意。

### 5.8.2 遍历字段与读取标签
```go
t := reflect.TypeOf(User{})

for i := 0; i < t.NumField(); i++ {
    f := t.Field(i)
    fmt.Printf("%s | %s | %s | %s\n",
        f.Name, f.Type, f.Tag.Get("json"), f.Tag.Get("gorm"))
}
```
输出依次是 `ID | uint | id | primaryKey`、`Name | string | name | size:64;not null`、`Email | string | email,omitempty | uniqueIndex`。

`f.Tag.Get("json")` 返回标签的完整值，包括 `,omitempty` 等选项；需要字段名时按逗号切分：`name := strings.Split(f.Tag.Get("json"), ",")[0]`。

### 5.8.3 修改值必须通过指针
```go
u := User{Name: "张三"}

v := reflect.ValueOf(u)
fmt.Println(v.CanSet()) // false，值不可修改

p := reflect.ValueOf(&u).Elem()
fmt.Println(p.CanSet()) // true
p.FieldByName("Name").SetString("李四")
fmt.Println(u.Name) // 李四
```
- `ValueOf(u)` 得到的是副本，不可设置；
- `ValueOf(&u).Elem()` 得到指针指向的可设置值；
- `CanSet` 为 false 时调用 `SetString` 会 panic；
- 未导出字段即使通过指针也不可设置。

### 5.8.4 为什么 JSON/GORM 能读标签

`encoding/json` 在序列化时大致做：

1. 用反射拿到结构体类型；
2. 遍历导出字段；
3. 读取 `json` 标签决定字段名和选项；
4. 用反射读取字段值，写入 JSON。

GORM 在初始化模型时做类似的事：

1. 反射解析结构体；
2. 读 `gorm` 标签得到列名、主键、索引、默认值；
3. 建立字段与列的映射，缓存起来；
4. 之后 CRUD 通过缓存和反射读写字段。

Gin 的参数绑定则读取 `json`、`form`、`uri`、`binding` 标签，把请求数据写入结构体。

这也解释了为什么：

- 字段必须导出；
- 标签拼错会静默失效；
- `ShouldBindJSON` 和 `db.Create` 需要指针（反射要写入）。

### 5.8.5 反射的边界

- 反射比直接字段访问慢，库会缓存类型信息；
- 业务代码不要用反射做常规字段读写；
- 不要用反射访问未导出字段；
- 反射适合写库、框架、序列化、通用校验；
- 能用接口或泛型解决时，优先不用反射。

## 5.9 构造函数 `NewXxx`

Go 没有构造函数语法，惯例是写一个 `NewXxx` 函数：
```go
type User struct {
    id   int
    Name string
    Age  int
}

func NewUser(name string, age int) *User {
    return &User{
        Name: name,
        Age:  age,
    }
}
```
使用：
```go
u := NewUser("张三", 25)
fmt.Println(u.Name) // 张三
```
为什么返回指针：

- 避免大结构体拷贝；
- 调用方拿到的是同一个对象，后续修改可见；
- 与 GORM/Gin 的指针惯例一致。

需要校验时返回 `(*User, error)`：
```go
func NewUser(name string, age int) (*User, error) {
    if name == "" {
        return nil, fmt.Errorf("name 不能为空")
    }
    if age < 0 || age > 150 {
        return nil, fmt.Errorf("age 超出范围: %d", age)
    }
    return &User{Name: name, Age: age}, nil
}
```
调用方必须检查错误：`u, err := NewUser("", 25); if err != nil { ... }`。

构造函数适合：

- 设置默认值；
- 校验参数；
- 初始化不可导出的字段；
- 建立内部依赖（repository、logger 等）。

不要在里面做重 I/O；需要 I/O 的初始化放到单独方法。

## 5.10 Functional Options

参数很多、大部分可选时，用函数选项模式：
```go
type Server struct {
    Host    string
    Port    int
    Timeout time.Duration
}

type Option func(*Server)

func WithHost(host string) Option {
    return func(s *Server) { s.Host = host }
}

func WithPort(port int) Option {
    return func(s *Server) { s.Port = port }
}

func WithTimeout(d time.Duration) Option {
    return func(s *Server) { s.Timeout = d }
}

func NewServer(opts ...Option) *Server {
    s := &Server{
        Host:    "127.0.0.1",
        Port:    8080,
        Timeout: 30 * time.Second,
    }
    for _, opt := range opts {
        opt(s)
    }
    return s
}
```
使用：
```go
s := NewServer(
    WithPort(9090),
    WithTimeout(10*time.Second),
)

fmt.Println(s.Host, s.Port, s.Timeout) // 127.0.0.1 9090 10s
```
优点：

- 默认值集中在构造函数；
- 调用方只写关心的参数；
- 新增选项不破坏已有调用；
- 选项可以有校验、可以组合。

缺点：

- 代码量比「配置结构体」多；
- 参数只有两三个时显得过度设计；
- 选项顺序会影响结果（后面的覆盖前面的）。

另一种常见写法是配置结构体：
```go
type ServerConfig struct {
    Host    string
    Port    int
    Timeout time.Duration
}

func NewServer(cfg ServerConfig) *Server { /* ... */ }
```
GORM 的 `gorm.Config` 就是这种思路。选择哪种取决于团队习惯和参数数量。

## 5.11 内存对齐（了解）

结构体字段按声明顺序排列，编译器会插入填充字节保证对齐。64 位平台上：
```go
type A struct {
    OK   bool    // 1 字节
    N    int64   // 8 字节，前面填充 7 字节
    Done bool    // 1 字节，后面填充 7 字节
} // 总大小 24

type B struct {
    N    int64   // 8
    OK   bool    // 1
    Done bool    // 1，后面填充 6
} // 总大小 16
```
可以用反射查看大小：`reflect.TypeOf(A{}).Size()` 为 24，`reflect.TypeOf(B{}).Size()` 为 16。

结论：

- 字段顺序会影响结构体大小；
- 把大字段放前面、小字段放后面通常更省内存；
- 日常业务结构体不必为此牺牲可读性；
- 只有在大量对象（百万级切片）或明确的内存瓶颈时，才值得调整。

> 本课程不展开 `unsafe`、`unsafe.Sizeof`、内存布局的完整规则。

## 5.12 常见错误与陷阱

### 5.12.1 速查表

| 错误/现象 | 原因 | 修复 |
|-----------|------|------|
| JSON 里没有字段 | 字段名小写，未导出 | 改成大写 |
| GORM 没有这一列 | 字段未导出 | 改成大写 |
| 加字段后编译失败 | 用了按位置初始化 | 改用字段名 |
| 方法修改不生效 | 值接收者 | 改用指针接收者 |
| 接口赋值失败 | 方法是指针接收者，却存了值 | 存 `&T{}` |
| `cannot call pointer method on T literal` | 字面量不可寻址 | 先赋给变量 |
| 嵌入字段访问 panic | 嵌入的是 nil 指针 | 初始化或判空 |
| `ambiguous selector` | 两个嵌入类型同名字段/方法 | 显式限定 |
| 标签完全没生效 | 键名拼错或分隔符写反 | json 逗号、gorm 分号 |
| `reflect: call of reflect.Value.SetString on zero Value` | 字段名不存在或未导出 | 检查字段名与导出性 |
| `reflect.Value.SetString using unaddressable value` | 没传指针 | `ValueOf(&u).Elem()` |
| 给外部类型加方法失败 | 方法只能定义在本包类型上 | 用包装结构体 |

### 5.12.2 值接收者改不了原对象

`func (u User) SetName(name string) { u.Name = name }` 改的是副本，调用后原对象不变；改成 `func (u *User) SetName(...)` 才生效。

### 5.12.3 方法集导致接口实现失败

如果 `Speak` 定义在 `*Cat` 上，`var s Speaker = Cat{}` 会编译失败；改成 `var s Speaker = &Cat{}`。这也是为什么同一类型的方法最好统一用指针接收者。

### 5.12.4 标签分隔符写反

`json:"name;omitempty"` 和 `gorm:"size:64,not null"` 都不会报错，但库解析不到预期内容。

正确写法是 `json:"name,omitempty" gorm:"size:64;not null"`。编译器不会报错，但库解析不到预期内容。

## 5.13 与 Gin/GORM 的关联

### 5.13.1 GORM 模型就是 struct
```go
type User struct {
    ID        uint      `gorm:"primaryKey"`
    Name      string    `gorm:"size:64;not null"`
    Email     string    `gorm:"uniqueIndex;size:128"`
    Age       int       `gorm:"default:18"`
    CreatedAt time.Time
    UpdatedAt time.Time
}
```
建表用 `db.AutoMigrate(&User{})`。GORM 的约定：

- `ID` 默认是主键；
- `CreatedAt` / `UpdatedAt` 自动维护；
- 表名默认是结构体名的复数（`User` → `users`）；
- 字段必须导出；
- 标签决定列名、类型、索引、默认值。

### 5.13.2 `gorm.Model` 通过嵌入提供通用字段

GORM 内部的 `gorm.Model` 大致如下（定义在 gorm 包内）：
```go
type Model struct {
    ID        uint      `gorm:"primarykey"`
    CreatedAt time.Time
    UpdatedAt time.Time
    DeletedAt DeletedAt `gorm:"index"`
}
```
使用：
```go
type User struct {
    gorm.Model
    Name string
}
```
`User` 就拥有了 `ID`、`CreatedAt`、`UpdatedAt`、`DeletedAt`，并支持软删除。这是嵌入的典型应用。

### 5.13.3 嵌入结构体的 GORM 标签

匿名字段会被 GORM 自动展开：
```go
type Address struct {
    City string
}

type User struct {
    gorm.Model
    Address Address `gorm:"embedded"`
}
```
命名嵌入需要 `embedded`；还可以加前缀：
```go
Address Address `gorm:"embedded;embeddedPrefix:addr_"`
```
列名会变成 `addr_city`。

### 5.13.4 Gin 参数绑定依赖标签
```go
type CreateUserRequest struct {
    Name  string `json:"name" binding:"required,min=2,max=20"`
    Email string `json:"email" binding:"required,email"`
    Age   int    `json:"age" binding:"gte=0,lte=120"`
}

var req CreateUserRequest
if err := c.ShouldBindJSON(&req); err != nil {
    c.JSON(400, gin.H{"error": err.Error()})
    return
}
```
- `json` 决定请求体字段名；
- `binding` 决定校验规则；
- 字段必须导出，否则绑定不到；
- 绑定失败返回 `error`，Gin 不会自动写响应，需要自己处理。

表单/查询绑定用 `form` 标签，例如 ``Page int `form:"page" binding:"gte=1"` ``，然后调用 `c.ShouldBindQuery(&req)`。

### 5.13.5 `json` 与 `gorm` 标签互不影响

``Password string `json:"-" gorm:"size:255"` `` 中，`json:"-"` 只让密码不出现在 API 响应里，GORM 仍然会读写 `password` 列；如果数据库也要忽略，写 `gorm:"-"`。两个标签可以同时存在，各管各的。

这是新手最容易误解的地方之一。

## 5.16 本章小结

| 概念 | 一句话解释 | 易错点 |
|------|------------|--------|
| struct | 字段的集合 | 字段顺序影响位置初始化和内存布局 |
| 导出 | 首字母大写 | 小写字段 JSON/GORM 都读不到 |
| `&T{}` | 创建并初始化指针 | 比 `new(T)` 更常用 |
| 可比较性 | 所有字段可比较才能 `==` | 含 slice/map/func 不可比较 |
| 值接收者 | 操作副本 | 修改不影响原对象 |
| 指针接收者 | 操作原对象 | 字面量不能直接调用 |
| 方法集 | `T` 只有值方法，`*T` 有全部 | 决定接口能否实现 |
| 嵌入 | 匿名字段，提升字段和方法 | 不是继承，没有子类型关系 |
| 标签 | 字段元数据 | json 逗号、gorm 分号 |
| 反射 | 运行时读类型和值 | 修改必须通过指针 |
| 构造函数 | `NewXxx` 惯例 | 校验时返回 `(*T, error)` |
| Options | 函数式可选参数 | 参数少时可能过度设计 |

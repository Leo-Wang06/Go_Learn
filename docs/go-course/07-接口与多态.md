## 7.1 从 TS 到 Go：接口是什么
TypeScript 的接口描述对象结构，`implements` 可以显式声明：

```ts
interface Shape {
  area(): number
  perimeter(): number
}

class Circle implements Shape {
  constructor(public r: number) {}
  area() { return Math.PI * this.r * this.r }
  perimeter() { return 2 * Math.PI * this.r }
}

function printShape(s: Shape) {
  console.log(s.area(), s.perimeter())
}
```

Go 的接口只描述**一组方法**，任何类型只要方法齐全，就自动满足：

```go
type Shape interface {
    Area() float64
    Perimeter() float64
}
```

| 维度 | TypeScript | Go |
|------|------------|-----|
| 接口内容 | 方法 + 属性 + 索引签名 | 只能是一组方法或嵌入接口 |
| 实现方式 | `implements` 或结构化兼容 | 隐式：方法齐全即实现 |
| 运行时 | 类型擦除后不存在 | 接口值带动态类型，运行时存在 |
| 空接口 | `{}` / `unknown` | `any`（`interface{}`） |

> **心智模型**：Go 的接口不是继承体系，而是「能力描述」。一个类型能做什么，比它是什么更重要。

## 7.2 接口定义与隐式实现
```go
package main
import (
    "fmt"
    "math"
)

type Shape interface {
    Area() float64
    Perimeter() float64
}

type Circle struct{ R float64 }
func (c Circle) Area() float64      { return math.Pi * c.R * c.R }
func (c Circle) Perimeter() float64 { return 2 * math.Pi * c.R }

type Rect struct{ W, H float64 }
func (r Rect) Area() float64      { return r.W * r.H }
func (r Rect) Perimeter() float64 { return 2 * (r.W + r.H) }

func PrintShape(s Shape) {
    fmt.Printf("%T: area=%.2f perimeter=%.2f\n", s, s.Area(), s.Perimeter())
}

func main() {
    PrintShape(Circle{R: 2})
    PrintShape(Rect{W: 3, H: 4})
}
```

输出：

```
main.Circle: area=12.57 perimeter=12.57
main.Rect: area=12.00 perimeter=14.00
```

`PrintShape` 接收 `Shape`，实际传入具体类型，调用各自的方法，这就是多态。

### 7.2.1 隐式实现的编译检查
```go
var s Shape = Circle{R: 2} // 通过：方法齐全
```

少一个方法就编译失败：

```go
type Line struct{ X1, Y1, X2, Y2 float64 }
func (l Line) Area() float64 { return 0 }

var s Shape = Line{} // 编译错误：Line does not implement Shape (missing method Perimeter)
```

好处：类型不需要为了接口改代码；可以为无法修改的第三方类型定义接口；接口由使用方定义。

### 7.2.2 一个类型可以实现多个接口
一个类型可以实现任意多个接口。例如 `Dog` 同时有 `Speak()` 和 `Move()`，就同时满足 `Speaker` 和 `Mover`；`var _ Speaker = Dog{}` 这种编译期断言在标准库和框架源码里非常常见。

## 7.3 接口值：动态类型 + 动态值
| 部分 | 含义 |
|------|------|
| 动态类型 | 当前装的具体类型，如 `main.Dog` |
| 动态值 | 当前装的具体值，如 `{旺财}` 或指针 |

```go
package main

import "fmt"

type Animal interface{ Sound() string }

type Dog struct{ Name string }

func (d Dog) Sound() string { return d.Name + " 汪汪" }

func main() {
    var a Animal
    fmt.Printf("零值: %T, %v, nil=%v\n", a, a, a == nil)

    a = Dog{Name: "旺财"}
    fmt.Printf("赋值后: %T, %v\n", a, a)

    var x any = a
    fmt.Printf("再赋给 any: %T, %v\n", x, x)
}
```

输出：

```
零值: <nil>, <nil>, nil=true
赋值后: main.Dog, {旺财}
再赋给 any: main.Dog, {旺财}
```

- 未赋值的接口是 nil 接口，`%T` 输出 `<nil>`；
- 赋值后 `%T` 输出动态类型，`%v` 输出动态值；
- 赋给 `any` 时，动态类型和动态值一起复制。

接口赋值是拷贝：`var a Animal = d` 之后修改 `d` 不影响接口里的值；若装的是 `&d`，拷贝的是指针。

## 7.4 nil 接口陷阱（重点）
```go
package main

import "fmt"

type MyError struct{ Msg string }

func (e *MyError) Error() string {
    if e == nil {
        return "<nil *MyError>"
    }
    return e.Msg
}

func bad() error {
    var e *MyError // nil 指针
    return e       // 把 nil 指针装进 error 接口
}

func good() error { return nil }

func main() {
    err := bad()
    fmt.Println(err == nil) // false
    fmt.Printf("%T\n", err) // *main.MyError
    fmt.Println(err)        // <nil *MyError>

    fmt.Println(good() == nil) // true

    var e *MyError
    fmt.Println(e == nil) // true
}
```

输出：

```
false
*main.MyError
<nil *MyError>
true
true
```

### 7.4.1 原因
`return e` 时，编译器把接口的动态类型设为 `*MyError`，动态值设为 `nil`，得到的接口值**本身不是 nil**。

| 表达式 | 动态类型 | 动态值 | `== nil` |
|--------|----------|--------|----------|
| `var e *MyError` | 不是接口 | `nil` | `true` |
| `var err error` | 无 | 无 | `true` |
| `err := bad()` | `*MyError` | `nil` | `false` |
| `err := good()` | 无 | 无 | `true` |

### 7.4.2 正确写法
```go
func find() error {
    var e *MyError
    if e == nil {
        return nil // 显式返回 nil 接口
    }
    return e
}
```

需要返回「没有错误」时，明确写 `return nil`，不要返回类型化的 nil 指针。

### 7.4.3 方法也可能 panic
接口非 nil，但里面装的指针是 nil，方法解引用接收者时仍会 panic。例如 `func (e *BadError) Error() string { return e.Msg }` 在 `e == nil` 时调用就会崩溃。所以 `err == nil` 只能判断接口本身，不能判断里面的指针。

## 7.5 空接口与 `any`
```go
type Any interface{}
```

Go 1.18 起 `any` 是 `interface{}` 的别名，完全等价。任何类型都满足空接口。

```go
package main

import "fmt"

func printAny(v any) {
    fmt.Printf("type=%T value=%v\n", v, v)
}

func main() {
    printAny(42)
    printAny("hello")
    printAny(nil)
}
```

输出：

```
type=int value=42
type=string value=hello
type=<nil> value=<nil>
```

`any` 会丢失静态类型：

```go
var x any = 42
// x + 1 // 编译错误
n, ok := x.(int)
if !ok {
    panic("not an int")
}
fmt.Println(n + 1) // 43
```

| 场景 | 建议 |
|------|------|
| 日志、JSON、容器等边界 | 可以用 `any` |
| 业务数据结构 | 用具体类型或泛型 |
| 拿到 `any` 后 | 尽快断言成具体类型 |

> 把 `any` 当 TypeScript 的 `any` 用，会让错误从编译期推迟到运行期。

## 7.6 类型断言
```go
v := x.(T) // 失败 panic
```

```go
package main

import "fmt"

func main() {
    var x any = "hello"

    s, ok := x.(string)
    fmt.Println(s, ok) // hello true

    n, ok := x.(int)
    fmt.Println(n, ok) // 0 false
}
```

输出：

```
hello true
0 false
```

断言失败时 `ok` 为 false，`v` 是该类型的零值。直接断言失败会 panic：

```go
n := x.(int) // panic: interface conversion: interface {} is string, not int
```

### 7.6.1 断言到接口
`T` 也可以是接口，表示「动态类型是否实现了这个接口」：

```go
var x any = Dog{Name: "旺财"}
s, ok := x.(Speaker)
fmt.Println(ok, s.Speak()) // true 旺财: 汪
```

### 7.6.2 对 nil 接口断言
```go
var x any
s, ok := x.(string)
fmt.Println(s, ok) // "" false
```

用 `comma-ok` 不会 panic；直接断言会 panic。

| 写法 | 失败行为 | 场景 |
|------|----------|------|
| `v := x.(T)` | panic | 类型确定，错误属于 bug |
| `v, ok := x.(T)` | 零值 + false | 外部输入，必须防御 |

## 7.7 `type switch`
```go
package main

import "fmt"

type Point struct{ X, Y int }

func (p Point) String() string { return fmt.Sprintf("(%d,%d)", p.X, p.Y) }

func describe(v any) {
    switch x := v.(type) {
    case nil:
        fmt.Println("nil 接口")
    case int:
        fmt.Printf("int: %d\n", x)
    case string:
        fmt.Printf("string: %q\n", x)
    case fmt.Stringer:
        fmt.Printf("Stringer: %s\n", x)
    default:
        fmt.Printf("其他类型: %T\n", x)
    }
}

func main() {
    describe(nil)
    describe(42)
    describe("go")
    describe(Point{1, 2})
    describe(3.14)
}
```

输出：

```
nil 接口
int: 42
string: "go"
Stringer: (1,2)
其他类型: float64
```

- `switch x := v.(type)` 只能用在 `switch` 中；
- 每个 `case` 里 `x` 就是对应类型；
- `case nil` 匹配 nil 接口；
- `case fmt.Stringer` 匹配实现了 `String()` 的类型；
- 从上到下匹配，**具体类型要写在接口之前**。如果 `fmt.Stringer` 写在 `Point` 前面，`Point` 会先被接口匹配，后面的 `case Point` 永远到不了；
- 不需要 `break`。

## 7.8 接口组合
接口可以嵌入其他接口，语义是「能力叠加」：

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}
type ReadWriter interface {
    Reader
    Writer
}
```

标准库 `io` 就是这样定义的，还有 `io.ReadCloser`、`io.WriteCloser`、`io.ReadWriteCloser`。

`bytes.Buffer` 实现了 `io.ReadWriter`，但没有 `Close`，所以不是 `io.ReadCloser`：

```go
var _ io.ReadWriter = (*bytes.Buffer)(nil)
// var _ io.ReadCloser = (*bytes.Buffer)(nil) // 编译错误
```

组合不是继承，不带来字段和实现，只表达「同时具备这些方法」。

## 7.9 小接口原则
| 接口 | 方法数 | 方法 |
|------|--------|------|
| `error` | 1 | `Error() string` |
| `fmt.Stringer` | 1 | `String() string` |
| `io.Reader` | 1 | `Read([]byte) (int, error)` |
| `io.Writer` | 1 | `Write([]byte) (int, error)` |
| `io.Closer` | 1 | `Close() error` |
| `http.Handler` | 1 | `ServeHTTP(http.ResponseWriter, *http.Request)` |

小接口容易实现、容易 mock、容易组合。

### 7.9.1 接口由使用方定义
```go
// service 包只定义自己需要的能力
type UserFinder interface {
    FindByID(ctx context.Context, id int64) (*User, error)
}

type UserService struct{ repo UserFinder }

func NewUserService(repo UserFinder) *UserService { return &UserService{repo: repo} }
```

repository 不需要知道 `UserFinder` 存在，只要方法匹配就自动实现。测试时传一个只实现 `FindByID` 的 fake 即可。

### 7.9.2 不要过早抽象
- 只有一个实现且没有 mock/替换需求：先用具体类型；
- 有两个以上实现或需要解耦：再抽接口；
- 接口超过 5 个方法：先考虑拆分。

> The bigger the interface, the weaker the abstraction. 接口越大，抽象越弱。

## 7.10 常用标准接口
### 7.10.1 `error`
```go
type error interface {
    Error() string
}
```

任何实现 `Error() string` 的类型都是错误，第 08 章展开。

### 7.10.2 `fmt.Stringer`
```go
type Stringer interface {
    String() string
}
```

```go
package main

import "fmt"

type Money struct {
    Amount   int64 // 以分为单位
    Currency string
}

func (m Money) String() string {
    return fmt.Sprintf("%s %.2f", m.Currency, float64(m.Amount)/100)
}

func main() {
    m := Money{Amount: 12345, Currency: "CNY"}
    fmt.Println(m) // CNY 123.45
}
```

输出：

```
CNY 123.45
```

`%v`、`%s`、`%+v` 都会调用 `String()`；想看字段用 `%#v`。实现时不要修改状态、不要 panic。

### 7.10.3 `io.Reader` 与 `io.Writer`
```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}
```

`Reader` 读取最多 `len(p)` 字节，返回读到的字节数 `n` 和错误，末尾返回 `io.EOF`；`Writer` 把 `p` 写入目标，若 `n < len(p)`，`err` 必须非 nil。

```go
package main
import (
    "bytes"
    "fmt"
    "io"
    "strings"
)

type UpperWriter struct{ W io.Writer }

func (u UpperWriter) Write(p []byte) (int, error) {
    return u.W.Write(bytes.ToUpper(p))
}

func main() {
    r := strings.NewReader("hello, 世界")
    buf := make([]byte, 5)
    n, err := r.Read(buf)
    fmt.Println(n, err, string(buf[:n])) // 5 <nil> hello

    data, err := io.ReadAll(r)
    fmt.Println(err, string(data)) // <nil> , 世界

    var out bytes.Buffer
    fmt.Fprint(UpperWriter{W: &out}, "hello, go")
    fmt.Println(out.String()) // HELLO, GO
}
```

输出：

```
5 <nil> hello
<nil> , 世界
HELLO, GO
```

调用方必须先处理 `n` 字节，再处理 `err`；包装已有 Writer 是常见的中间件式设计。

### 7.10.4 `io.Closer`
```go
type Closer interface {
    Close() error
}
```

文件、连接、HTTP 响应体都实现它。典型用法是 `defer f.Close()`，也可以用 `var _ io.Closer = (*os.File)(nil)` 做编译期断言。

### 7.10.5 `http.Handler`
```go
type Handler interface {
    ServeHTTP(w http.ResponseWriter, r *http.Request)
}
```

```go
package main
import (
    "fmt"
    "net/http"
    "net/http/httptest"
)

type HelloHandler struct{}

func (h HelloHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK)
    fmt.Fprintf(w, "hello, %s", r.URL.Path)
}

func main() {
    req := httptest.NewRequest(http.MethodGet, "/go", nil)
    rec := httptest.NewRecorder()
    HelloHandler{}.ServeHTTP(rec, req)
    fmt.Println(rec.Code, rec.Body.String()) // 200 hello, /go
}
```

输出：

```
200 hello, /go
```

`http.HandlerFunc` 是适配器，把普通函数变成 `Handler`：

```go
type HandlerFunc func(w http.ResponseWriter, r *http.Request)

func (f HandlerFunc) ServeHTTP(w http.ResponseWriter, r *http.Request) { f(w, r) }
```

### 7.10.6 `driver.Valuer` 与 `sql.Scanner`
```go
type Valuer interface {
    Value() (driver.Value, error)
}
type Scanner interface {
    Scan(src any) error
}
```

`driver.Valuer` 负责 Go 值 → 数据库值，`sql.Scanner` 负责数据库值 → Go 值。GORM 写库时调用 `Value()`，查库回填时调用 `Scan()`。

```go
package main

import (
    "database/sql"
    "database/sql/driver"
    "fmt"
)

type Status string

func (s Status) Value() (driver.Value, error) { return string(s), nil }

func (s *Status) Scan(src any) error {
    switch v := src.(type) {
    case string:
        *s = Status(v)
    case []byte:
        *s = Status(string(v))
    case nil:
        *s = ""
    default:
        return fmt.Errorf("status: cannot scan %T", src)
    }
    return nil
}

var _ driver.Valuer = Status("")
var _ sql.Scanner = (*Status)(nil)

func main() {
    v, err := Status("active").Value()
    fmt.Println(v, err) // active <nil>

    var s Status
    _ = s.Scan([]byte("disabled"))
    fmt.Println(s) // disabled
}
```

输出：

```
active <nil>
disabled
```

`Scan` 必须用指针接收者；数据库可能传 `string`、`[]byte` 或 `nil`，都要处理。

## 7.11 方法集与接口
| 类型 | 方法集包含 |
|------|------------|
| `T` | 所有值接收者方法 |
| `*T` | 值接收者方法 + 指针接收者方法 |

值接收者：`T` 和 `*T` 都能实现接口。

```go
type Speaker interface{ Speak() string }

type Dog struct{ Name string }

func (d Dog) Speak() string { return d.Name + ": 汪" }

var _ Speaker = Dog{}  // 可以
var _ Speaker = &Dog{} // 也可以
```

指针接收者：只有 `*T` 能实现。

```go
type Robot struct{ ID int }

func (r *Robot) Speak() string { return fmt.Sprintf("robot-%d: beep", r.ID) }

var _ Speaker = &Robot{ID: 7} // 可以
// var _ Speaker = Robot{ID: 8} // 编译错误：method Speak has pointer receiver
```

### 7.11.1 可寻址时的自动取地址
```go
var r Robot
r.Speak() // 等价于 (&r).Speak()
```

但不可寻址的值不行：

```go
Robot{ID: 1}.Speak() // 编译错误：cannot call pointer method on Robot

m := map[string]Robot{"a": {ID: 1}}
m["a"].Speak() // 编译错误：map 元素不可寻址
```

正确写法：

```go
r := m["a"]
r.Speak()

// 或者 map 里存指针
mp := map[string]*Robot{"a": {ID: 1}}
mp["a"].Speak()
```

需要修改接收者、结构体较大、含 `sync.Mutex` 时用指针；小且不可变的值（如 `time.Time`）可以用值；同一类型尽量统一用一种接收者。

## 7.12 接口比较与切片限制
先比动态类型，再比动态值：

```go
var a any = 1
var b any = 1
var c any = "1"

fmt.Println(a == b) // true
fmt.Println(a == c) // false
```

动态类型不可比较时会 panic：

```go
var a any = []int{1}
var b any = []int{1}
fmt.Println(a == b) // panic: comparing uncomparable type []int
```

`[]T` 不能直接赋给 `[]any`：

```go
ints := []int{1, 2, 3}

// var anys []any = ints // 编译错误

anys := make([]any, len(ints))
for i, v := range ints {
    anys[i] = v
}
fmt.Println(anys...) // 1 2 3
```

两者内存布局不同；函数参数 `func([]any)` 也不能接收 `[]int`。

> 底层表示（概念）：空接口通常是「类型信息 + 数据指针」，非空接口还需要方法表（itab）。日常只需记住动态类型 + 动态值。

## 7.13 与 Gin/GORM 的关联
### 7.13.1 Gin 的 `Engine` 实现 `http.Handler`
```go
func (engine *Engine) ServeHTTP(w http.ResponseWriter, req *http.Request)
```

`http.ListenAndServe` 的参数是 `http.Handler`，所以 `http.ListenAndServe(":8080", gin.Default())` 可以直接使用。Gin 因此能无缝接入标准库生态。

### 7.13.2 `gin.HandlerFunc`
```go
type HandlerFunc func(*Context)
```

它是函数类型，不是接口：

```go
r.GET("/ping", func(c *gin.Context) {
    c.JSON(200, gin.H{"message": "pong"})
})
```

`GET` 的签名大致是：

```go
func (group *RouterGroup) GET(relativePath string, handlers ...HandlerFunc) IRoutes
```

匿名函数被转换成 `gin.HandlerFunc`；`...HandlerFunc` 允许传多个 handler（中间件 + 最终 handler）；返回 `IRoutes` 支持链式调用。

### 7.13.3 `IRoutes` 与 `IRouter`
```go
type IRoutes interface {
    Use(...HandlerFunc) IRoutes
    GET(string, ...HandlerFunc) IRoutes
    POST(string, ...HandlerFunc) IRoutes
    // ... 其他 HTTP 方法
}

type IRouter interface {
    IRoutes
    Group(string, ...HandlerFunc) *RouterGroup
}
```

`*gin.Engine` 和 `*gin.RouterGroup` 都实现了这些接口。文档里的 `IRoutes` 表示「还能继续注册路由」。

### 7.13.4 `gorm.Plugin`
```go
type Plugin interface {
    Name() string
    Initialize(*DB) error
}
```

```go
type MyPlugin struct{}

func (p *MyPlugin) Name() string { return "my-plugin" }

func (p *MyPlugin) Initialize(db *gorm.DB) error { return nil }

db.Use(&MyPlugin{})
```

`db.Use` 接收 `gorm.Plugin`，任何实现这两个方法的类型都能注册。

### 7.13.5 用接口做依赖倒置与 mock
```go
type UserRepo interface {
    FindByID(ctx context.Context, id int64) (*User, error)
    Create(ctx context.Context, u *User) error
}

type UserService struct{ repo UserRepo }

func NewUserService(repo UserRepo) *UserService { return &UserService{repo: repo} }
```

测试时不需要数据库：

```go
type fakeUserRepo struct{ users map[int64]*User }

func (f *fakeUserRepo) FindByID(ctx context.Context, id int64) (*User, error) {
    if u, ok := f.users[id]; ok {
        return u, nil
    }
    return nil, gorm.ErrRecordNotFound
}

func (f *fakeUserRepo) Create(ctx context.Context, u *User) error {
    f.users[u.ID] = u
    return nil
}
```

`fakeUserRepo` 自动实现 `UserRepo`，这是隐式接口在测试中的最大价值。

### 7.13.6 `c.Get` 返回 `any`
```go
c.Set("userID", int64(42))
v, ok := c.Get("userID")
if !ok {
    return
}
id, ok := v.(int64)
if !ok {
    return
}
```

必须用 `comma-ok`，因为 `c.Get` 返回 `(any, bool)`。

## 7.14 常见错误与陷阱
| 错误/现象 | 原因 | 修复 |
|-----------|------|------|
| `err == nil` 为 false，打印却是 nil | 接口里装了 nil 指针 | 直接返回 `nil` |
| `x.(T)` panic | 类型不匹配 | 用 `comma-ok` |
| `[]int` 不能赋给 `[]any` | 内存布局不同 | 逐个转换 |
| 值类型无法满足指针接收者接口 | 方法集不含指针方法 | 传 `&T{}` |
| `T{}.PtrMethod()` 编译失败 | 字面量不可寻址 | 先赋变量或用 `&T{}` |
| `m[k].PtrMethod()` 编译失败 | map 元素不可寻址 | 取出到局部变量 |
| 接口比较 panic | 动态类型是 slice/map/func | 不要比较这类值 |
| `case fmt.Stringer` 抢占具体类型 | 匹配顺序问题 | 具体类型放前面 |
| 接口方法调用 panic | 接口里是 nil 指针 | 判断 nil 或避免类型化 nil |
| `any` 滥用 | 丢失类型信息 | 边界用 `any`，内部用具体类型 |
| 大接口难 mock | 方法太多 | 拆成小接口 |

两个高频细节：

```go
var p *MyError  // 具体指针，p == nil 为 true
var e error = p // 接口，e == nil 为 false
```

值接收者方法改的是副本，需要修改状态时用指针接收者并传指针。

## 7.17 本章小结
| 概念 | 一句话解释 | 易错点 |
|------|------------|--------|
| 接口 | 一组方法签名 | 不能有字段 |
| 隐式实现 | 方法齐全即实现 | 不需要 `implements` |
| 接口值 | 动态类型 + 动态值 | `%T` 看动态类型 |
| nil 接口 | 没有动态类型和值 | 装 nil 指针后不等于 nil |
| `any` | 空接口别名 | 滥用会丢失类型安全 |
| 类型断言 | 取出动态类型 | 不带 ok 会 panic |
| `type switch` | 按动态类型分支 | 具体类型写在接口前 |
| `Stringer` | `String() string` | `%v`/`%s`/`%+v` 都会调用 |
| `io.Reader` | `Read([]byte) (int, error)` | 先处理 n 再处理 err |
| `io.Writer` | `Write([]byte) (int, error)` | `n < len(p)` 时 err 非 nil |
| `http.Handler` | `ServeHTTP(w, r)` | Gin Engine 实现了它 |
| `driver.Valuer` | Go → 数据库 | `Value() (driver.Value, error)` |
| `sql.Scanner` | 数据库 → Go | `Scan(any) error`，指针接收者 |
| 方法集 | `T` 只有值方法，`*T` 全有 | 指针接收者接口只能用 `*T` |

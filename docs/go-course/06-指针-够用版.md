# 第 06 章：指针（够用版）

> **阶段**：阶段二 · 类型系统与抽象
> **建议时间**：1 天
> **前置知识**：第 01–05 章（变量、结构体、方法、值传递）
> **代码基准**：Go 1.22 及以上

## 本章目标

学完本章，你应当能够：

1. 正确使用 `&` 取地址、`*` 解引用；
2. 读懂指针类型 `*T`，解释指针的零值 `nil`；
3. 用指针参数修改调用方变量，用指针返回值表达「可能不存在」；
4. 分清 `new(T)` 与 `&T{}`；
5. 判断什么时候必须用指针、什么时候不该用；
6. 解释 GORM 为什么要求 `db.Create(&user)`、`db.First(&user, id)`；
7. 用指针字段表达数据库 NULL / JSON `null`；
8. 识别并避免常见的 nil 指针 panic。

> 本章不展开逃逸分析的推导过程，只给结论；不涉及 `unsafe.Pointer` 的用法。

## 6.1 变量、地址与指针

### 6.1.1 变量住在内存里

把变量想成一个带名字的盒子：名字是 `x`，里面装着值 `42`，盒子有一个内存地址。

```go
x := 42

fmt.Println(x)  // 42，值
fmt.Println(&x) // 类似 0xc0000120d8，地址（每次运行可能不同）
```

`&x` 读出 `x` 的地址；地址的类型是 `*int`（指向 `int` 的指针）。

### 6.1.2 取地址 `&` 与解引用 `*`

```go
x := 42
p := &x // p 是 *int，保存 x 的地址

fmt.Println(p)  // 0xc0000120d8（类似）
fmt.Println(*p) // 42，解引用：顺着地址找到值

*p = 100        // 通过指针修改 x
fmt.Println(x)  // 100
```

两个符号不要混淆：

| 写法 | 含义 | 例子 |
|------|------|------|
| `&x` | 取地址，得到 `*T` | `p := &x` |
| `*p` | 解引用，得到 `T` | `v := *p` |
| `*T` | 指针类型 | `var p *int` |
| `**T` | 指向指针的指针 | `var pp **int` |

`*` 在类型里表示「指针」，在表达式里表示「解引用」，位置不同，含义不同。

### 6.1.3 指针本身也是值

指针是一个普通值，可以赋值、传参、比较：

```go
x := 42
p1 := &x
p2 := p1

fmt.Println(p1 == p2) // true，指向同一地址
fmt.Printf("%T\n", p1) // *int
```

把指针传给函数，拷贝的是地址；函数通过地址能修改原变量。

### 6.1.4 指针类型

```go
var pInt *int
var pStr *string
var pUser *User

fmt.Printf("%T %T %T\n", pInt, pStr, pUser) // *int *string *main.User
```

指针类型由「指向的类型」决定：

- `*int` 不能赋给 `*int64`；
- `*User` 和 `*Order` 是不同类型；
- 指针之间不能做算术运算（没有 C 的 `p++`）。

## 6.2 nil 指针

### 6.2.1 指针的零值是 nil

```go
var p *int

fmt.Println(p)        // <nil>
fmt.Println(p == nil) // true
```

声明但未指向任何对象的指针是 `nil`。对 nil 指针解引用会 panic：

```go
var p *int
fmt.Println(*p) // panic: runtime error: invalid memory address or nil pointer dereference
```

### 6.2.2 使用前判空

```go
func printValue(p *int) {
    if p == nil {
        fmt.Println("空指针")
        return
    }
    fmt.Println(*p)
}

var p *int
printValue(p) // 空指针

x := 10
printValue(&x) // 10
```

指针参数、指针返回值、结构体里的指针字段，使用前都要考虑 nil。

### 6.2.3 nil 指针可以比较

```go
var p *User
var q *User

fmt.Println(p == nil) // true
fmt.Println(p == q)   // true，都是 nil
```

指针只能和同类型指针或 `nil` 比较，不能跨类型比较。

## 6.3 指针作为参数

### 6.3.1 修改调用方的变量

Go 只有值传递。传 `int` 改不了调用方，传 `*int` 可以：

```go
func double(n *int) {
    *n = *n * 2
}

func main() {
    x := 10
    double(&x)
    fmt.Println(x) // 20
}
```

执行过程：

1. `&x` 把地址传给 `double`；
2. `n` 是地址的副本，但指向同一个 `x`；
3. `*n = *n * 2` 修改的是 `x` 本身。

### 6.3.2 修改结构体字段

```go
type User struct {
    Name string
    Age  int
}

func birthday(u *User) {
    u.Age++ // 自动解引用，等价于 (*u).Age++
}

func main() {
    u := User{Name: "张三", Age: 25}
    birthday(&u)
    fmt.Println(u.Age) // 26
}
```

如果传值 `func birthday(u User)`，修改的是副本，调用方看不到变化。

### 6.3.3 值传递对照

| 函数签名 | 函数内拿到 | 能否修改调用方 |
|----------|------------|----------------|
| `f(n int)` | 值的副本 | 否 |
| `f(n *int)` | 地址的副本 | 是，通过 `*n` |
| `f(u User)` | 结构体副本 | 否 |
| `f(u *User)` | 地址的副本 | 是，通过 `u.Field` |
| `f(s []int)` | 切片头副本 | 修改元素可以；长度不一定 |
| `f(m map[K]V)` | map 引用副本 | 增删改可以 |
| `f(ch chan T)` | channel 引用副本 | 发送/接收可以 |

### 6.3.4 什么时候不需要指针参数

- 只读的小结构体，传值更安全；
- 希望函数拿到一份独立快照，避免被调用方后续修改影响；
- 类型本身已经是引用语义（slice、map、chan），通常不需要再取地址；
- 为了「看起来像 Java」而给所有参数加指针，只会增加 nil 检查负担。

## 6.4 指针作为返回值

### 6.4.1 返回局部变量地址是安全的

```go
func newInt(v int) *int {
    x := v
    return &x
}

func main() {
    p := newInt(10)
    fmt.Println(*p) // 10
}
```

在 C 里返回局部变量地址是悬空指针；Go 不会。编译器会做逃逸分析：如果局部变量的地址逃出了函数，就把它分配到堆上，由 GC 管理。

结论：

- 返回 `&x` 是安全的；
- 不需要手动 malloc/free；
- 不要因为「怕悬空」而避免返回指针；
- 逃逸分析的具体决策不需要掌握，性能问题用 benchmark 和 pprof 判断。

想观察编译器决策，可以运行：

```
go build -gcflags="-m" .
```

可能看到 `moved to heap: x`。这属于诊断信息，不是日常必学内容。

### 6.4.2 用 nil 表示「不存在」

```go
func findUser(id int) *User {
    if id <= 0 {
        return nil
    }
    return &User{ID: id, Name: "张三"}
}

u := findUser(0)
if u == nil {
    fmt.Println("用户不存在")
} else {
    fmt.Println(u.Name)
}
```

指针返回值的语义清晰：`nil` 表示没有结果。调用方必须判空。

另一种做法是返回 `(User, bool)` 或 `(User, error)`。选择取决于语义：

- 「没找到」是正常分支 → `*User` + nil，或 `(User, bool)`；
- 「没找到」是错误 → `(User, error)`；
- 结构体很大且可能不存在 → `*User`。

## 6.5 `new(T)` 与 `&T{}`

```go
p1 := new(int)  // *int，指向 0
p2 := new(User) // *User，所有字段零值

p3 := &User{}          // 同上，零值
p4 := &User{Name: "张三"} // 可以初始化

fmt.Println(*p1) // 0
fmt.Println(p2)  // &{ 0}
fmt.Println(p4)  // &{ 张三 0}
```

| 写法 | 返回 | 能否初始化 | 适用场景 |
|------|------|------------|----------|
| `new(T)` | `*T` | 否 | 需要零值指针，泛型/底层代码 |
| `&T{}` | `*T` | 是 | 业务代码，推荐 |
| `make([]T, ...)` | `[]T` | 是 | 只用于 slice/map/chan |

注意：

- `new` 返回指针，`make` 返回值；
- `new([]int)` 得到 `*[]int`，指向一个 nil 切片，很少用；
- 需要空切片时写 `make([]int, 0)`，不是 `new([]int)`。

## 6.6 结构体指针与自动解引用

### 6.6.1 `p.Field` 等价于 `(*p).Field`

```go
type User struct {
    Name string
    Age  int
}

p := &User{Name: "张三", Age: 25}

fmt.Println(p.Name)    // 张三
fmt.Println((*p).Name) // 张三，显式写法
p.Age = 26
fmt.Println(p.Age)     // 26
```

Go 自动解引用，所以结构体指针用起来和结构体一样。方法调用也自动取地址/解引用：

```go
func (u *User) SetName(name string) { u.Name = name }

u := User{Name: "张三"}
u.SetName("李四") // 自动变成 (&u).SetName("李四")
fmt.Println(u.Name) // 李四
```

### 6.6.2 可寻址规则

`&` 只能作用于**可寻址**的值：

| 表达式 | 能否取地址 | 原因 |
|--------|------------|------|
| 变量 `x` | 能 | 有固定位置 |
| 切片元素 `s[i]` | 能 | 底层数组元素 |
| 数组元素 `a[i]` | 能 | 数组元素 |
| 结构体字段 `u.Name` | 能（u 可寻址时） | 字段有固定偏移 |
| 复合字面量 `&User{}` | 能 | 语法允许 |
| 常量 `42` | 不能 | 没有地址 |
| map 元素 `m[k]` | 不能 | 扩容会搬家 |
| 函数返回值 `f().Field` | 不能 | 临时值 |
| 接口方法返回值 | 不能 | 临时值 |

这解释了第 04 章的现象：

```go
m := map[string]int{"a": 1}
// p := &m["a"] // 编译错误：cannot take address of m["a"]
```

需要地址时，先取出到变量：

```go
v := m["a"]
p := &v
```

### 6.6.3 嵌套指针

```go
type Node struct {
    Value int
    Next  *Node
}

head := &Node{Value: 1}
head.Next = &Node{Value: 2}

fmt.Println(head.Value)      // 1
fmt.Println(head.Next.Value) // 2
fmt.Println(head.Next.Next)  // <nil>
```

链表、树、图等递归结构必须用指针，否则类型无法定义（结构体不能直接包含自身）。

## 6.7 什么时候必须用指针

### 6.7.1 需要修改原值

```go
func (u *User) Rename(name string) { u.Name = name }
func increment(n *int)             { *n = *n + 1 }
```

这是最常见、最没有争议的理由。

### 6.7.2 避免大对象拷贝

结构体很大时，每次传值都要复制。指针只复制一个地址：

```go
type Big struct {
    Data [1024 * 1024]byte
}

func process(b *Big) { /* ... */ }
```

但不要凭感觉优化。小结构体传值往往更快（栈上分配、缓存友好），是否用指针应以 benchmark 为准。

### 6.7.3 表达「可选 / 未设置」

`int` 的零值是 0，无法区分「值是 0」和「没有设置」。`*int` 可以：

```go
type UpdateRequest struct {
    Age *int `json:"age"`
}
```

`nil` 表示未提供，非 nil 表示提供了值（包括 0）。这是 PATCH 接口和 GORM 可空字段的常用手法。

### 6.7.4 方法集与接口

如果方法使用指针接收者，只有 `*T` 实现接口：

```go
type Speaker interface{ Speak() string }

type Cat struct{}
func (c *Cat) Speak() string { return "喵" }

var s Speaker = &Cat{} // 正确
// var s2 Speaker = Cat{} // 编译错误
```

需要把对象存进接口并调用指针方法时，必须存指针。

### 6.7.5 共享同一份状态

多个函数/goroutine 需要操作同一个对象时，传指针可以避免各自持有副本。但要小心并发读写，必要时加锁（第 11 章）。

### 6.7.6 递归数据结构

链表、树、图、双向队列等需要指针连接节点。值类型无法形成递归包含。

### 6.7.7 什么时候不用指针

- 小结构体、只读数据；
- 希望值语义（赋值即独立副本）；
- 类型本身已经是引用语义（slice、map、chan）；
- 接口值通常不需要 `*interface{}`；
- 不想引入 nil 检查和可变共享；
- 没有测量就「为了性能」到处加指针。

经验法则：**先写清楚，再测量，最后才优化。**

## 6.8 指针与 GORM

### 6.8.1 为什么 `db.Create(&user)` 要传指针

```go
user := User{Name: "张三"}

if err := db.Create(&user).Error; err != nil {
    // 处理错误
}

fmt.Println(user.ID) // 自增主键被回填，例如 1
```

GORM 需要：

1. 通过反射读取字段，生成 INSERT；
2. 把数据库生成的自增 ID、时间戳**写回**你的变量；
3. 保证写入的是调用方持有的对象，而不是一个副本。

反射修改值要求目标可寻址；`&user` 提供了可寻址的目标。传值 `db.Create(user)` 时，即使内部能读到数据，也无法把 ID 写回调用方的 `user`。所以 GORM 文档的所有示例都传指针。

### 6.8.2 查询必须传指针接收结果

```go
var user User
err := db.First(&user, 1).Error
if err != nil {
    // 处理错误
}
fmt.Println(user.Name)
```

`First` 把查询结果写入 `&user` 指向的结构体。传值的话，结果写进副本，调用方拿到的还是零值。

查询切片：

```go
var users []User
db.Where("age > ?", 18).Find(&users)
```

这里必须传 `&users`，因为 GORM 不仅要写元素，还要修改切片的**长度和底层数组指针**（切片头）。传 `users` 只会改到切片头的副本。

### 6.8.3 `Model` 与链式调用

```go
db.Model(&User{}).Where("age > ?", 18).Find(&users)
```

- `Model(&User{})` 告诉 GORM 表名和模型类型；
- 链式方法返回 `*gorm.DB`，所以可以继续 `.Where().Order().Limit()`；
- 每个操作最终通过 `.Error` 取错误，通过 `.RowsAffected` 取影响行数。

```go
result := db.Model(&User{}).Where("age > ?", 18).Find(&users)
fmt.Println(result.Error, result.RowsAffected)
```

### 6.8.4 更新：零值陷阱

GORM 用结构体更新时，默认忽略零值字段：

```go
db.Model(&user).Updates(User{Name: "李四"}) // 只更新 Name
db.Model(&user).Updates(User{Age: 0})       // Age=0 是零值，可能不会更新
```

要更新零值，用 map 或 Select：

```go
db.Model(&user).Updates(map[string]any{
    "name": "",
    "age":  0,
})

db.Model(&user).Select("Name", "Age").Updates(User{Name: "", Age: 0})
```

单字段更新也可以直接指定：

```go
db.Model(&user).Update("age", 0)
```

### 6.8.5 指针字段与数据库 NULL

```go
type User struct {
    ID   uint
    Name string
    Age  *int // 可以为 NULL
}
```

- `Age == nil` → 数据库存 `NULL`；
- `Age != nil` → 存指针指向的值，包括 0；
- 查询到 NULL 时，GORM 把字段设为 nil。

```go
age := 0
u1 := User{Name: "张三", Age: &age} // 存 0
u2 := User{Name: "李四"}            // 存 NULL
fmt.Println(u1.Age != nil, u2.Age == nil) // true true
```

替代方案是 `sql.NullInt64`：

```go
type User struct {
    Age sql.NullInt64 // Valid=false 表示 NULL
}
```

`*int` 在 JSON 和业务代码里更自然；`sql.NullInt64` 更贴近 `database/sql`。团队选一种即可。

### 6.8.6 指针字段与零值更新

指针字段常被用来「显式设置零值」：`Age: &zero`（`zero := 0`）在语义上表示「设置了年龄，值为 0」。但 GORM 文档明确保证的零值更新方式是 **map 或 Select**；如果团队用指针字段表达零值，要统一约定并写测试验证当前 GORM 版本的行为。

### 6.8.7 常见 GORM 指针错误

| 写法 | 问题 |
|------|------|
| `db.Create(user)` | ID/时间戳无法回填到调用方 |
| `db.First(user, 1)` | 无法写入调用方，通常报错或得到零值 |
| `db.Find(users)` | 切片头无法更新，结果丢失 |
| `db.Model(User{})` | 部分场景可以，但语义不如 `&User{}` 清晰 |
| `db.Model(&user).Updates(User{Age: 0})` | 零值被忽略 |
| `var u *User; db.First(u)` | nil 指针，GORM 无法写入，报错 |

## 6.9 指针与 JSON

### 6.9.1 nil 指针字段输出 `null`

```go
type User struct {
    Name string `json:"name"`
    Age  *int   `json:"age"`
}

b, _ := json.Marshal(User{Name: "张三"})
fmt.Println(string(b)) // {"name":"张三","age":null}

age := 0
b, _ = json.Marshal(User{Name: "张三", Age: &age})
fmt.Println(string(b)) // {"name":"张三","age":0}
```

指针字段能区分：

- `nil` → JSON `null`；
- 指向 0 → JSON `0`。

如果用 `Age int`，两者都会输出 `0`，无法表达「未设置」。

### 6.9.2 `omitempty` 与指针

```go
type Req struct {
    Name string `json:"name,omitempty"`
    Age  *int   `json:"age,omitempty"`
}

b, _ := json.Marshal(Req{})
fmt.Println(string(b)) // {}

age := 0
b, _ = json.Marshal(Req{Age: &age})
fmt.Println(string(b)) // {"age":0}
```

`omitempty` 对指针的规则：

- nil 指针 → 省略；
- 非 nil 指针 → 输出，即使指向零值。

这正是 PATCH 请求想要的行为：没传的字段不出现，传了 0 就输出 0。

### 6.9.3 PATCH 请求结构体

```go
type PatchUserRequest struct {
    Name *string `json:"name"`
    Age  *int    `json:"age"`
}

func PatchUser(c *gin.Context) {
    var req PatchUserRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }

    if req.Name != nil {
        // 更新姓名
    }
    if req.Age != nil {
        // 更新年龄，*req.Age 可能是 0
    }
}
```

`nil` 表示「请求里没提供」，非 nil 表示「提供了，按值更新」。

一个限制：`*T` 无法区分「字段不存在」和「字段显式传 null」。需要严格区分时，用 `json.RawMessage` 或自定义可选类型。

### 6.9.4 JSON 解码到指针

```go
var age *int
json.Unmarshal([]byte("0"), &age)
fmt.Println(*age) // 0

var age2 *int
json.Unmarshal([]byte("null"), &age2)
fmt.Println(age2 == nil) // true
```

解码 `null` 会把指针设为 nil；解码数字会分配新值。

## 6.10 多级指针（了解）

```go
x := 1
p := &x  // *int
pp := &p // **int

fmt.Println(**pp) // 1
**pp = 2
fmt.Println(x) // 2
```

多级指针的典型用途是「让函数修改调用方的指针变量」：

```go
func reset(p **int) {
    *p = nil
}

x := 1
p := &x
reset(&p)
fmt.Println(p == nil) // true
```

日常业务几乎用不到 `**T`。看到 `**T` 时，先想清楚「要修改的是指针本身，还是指针指向的值」。

`unsafe.Pointer` 可以绕过类型系统，本课程不展开，业务代码不要使用。

## 6.11 常见错误与陷阱

### 6.11.1 速查表

| 错误/现象 | 原因 | 修复 |
|-----------|------|------|
| nil pointer dereference | 指针没初始化就解引用 | 判空或初始化 |
| 函数返回 nil，调用方直接用了 | 没检查返回值 | `if p != nil` |
| `cannot take address of 42` | 常量不可寻址 | 先赋给变量 |
| `cannot take address of m[k]` | map 元素不可寻址 | 取出到变量 |
| 指针改不了切片长度 | 传的是切片头副本 | 返回新切片或传 `*[]T` |
| `&u` 修改后原对象没变 | 传的是值副本 | 传指针 |
| 循环里 `&u` 拿到副本地址 | `u` 是元素副本 | 用 `&users[i]` |
| 比较指针以为在比较值 | `==` 比的是地址 | 比较 `*p` 或写 Equal |
| `db.Create(user)` 没有 ID | 没传指针 | `db.Create(&user)` |
| `db.Find(users)` 结果为空 | 切片头没被更新 | `db.Find(&users)` |
| `new([]int)` 得到的是 `*[]int` | 不是切片，不能直接 `append` | 用 `make([]int, 0)` |
| 指针字段 nil 当 0 用 | 没判空 | 先判 nil |
| 并发读写同一指针 | 数据竞争 | 加锁或避免共享 |
| `*interface{}` 解引用混乱 | 指向接口的指针很少需要 | 直接用接口 |

### 6.11.2 循环变量地址

```go
users := []User{{Name: "a"}, {Name: "b"}}

var ptrs []*User
for _, u := range users {
    ptrs = append(ptrs, &u)
}

ptrs[0].Name = "x"
fmt.Println(users[0].Name) // a，没有被修改
```

Go 1.22 起每次迭代都会新建 `u`，所以 `ptrs[0]` 和 `ptrs[1]` 地址不同；但 `u` 仍然是元素的**副本**，修改它不会修改切片元素。

要拿到元素本身的地址：

```go
for i := range users {
    ptrs = append(ptrs, &users[i])
}
```

### 6.11.3 指针比较不是值比较

```go
a := 1
p1 := &a
p2 := &a
fmt.Println(p1 == p2) // true，同一地址

b := 1
p3 := &b
fmt.Println(p1 == p3) // false，不同地址
fmt.Println(*p1 == *p3) // true，值相同
```

判断两个指针是否指向「相等的值」，要解引用后比较；结构体可能还需要逐字段比较。

### 6.11.4 nil 指针方法

指针接收者方法可以在 nil 指针上调用，但方法内部必须先判空：

```go
func (u *User) SafeName() string {
    if u == nil {
        return ""
    }
    return u.Name
}

var u *User
fmt.Println(u.SafeName()) // ""
```

如果方法内直接 `u.Name`，仍然会 panic。

## 6.12 与 Gin/GORM 的关联

### 6.12.1 `*gin.Context` 为什么是指针

```go
func handler(c *gin.Context) {
    c.JSON(200, gin.H{"message": "ok"})
}
```

`Context` 保存了一次请求的状态：请求、响应、参数、中间件数据。Gin 在整条 handler 链中传递同一个 `*Context`：

- 中间件 `c.Set` 写入的值，后续 handler 能读到；
- `c.Next()` 推进链；
- `c.Abort()` 中止链；
- 响应状态和 writer 都挂在同一个对象上。

如果传值，每个 handler 拿到副本，状态就分裂了。

### 6.12.2 请求绑定需要指针

```go
var req CreateUserRequest
if err := c.ShouldBindJSON(&req); err != nil {
    c.JSON(400, gin.H{"error": err.Error()})
    return
}
```

`ShouldBindJSON` 内部用反射/JSON 解码把请求体写入 `req`。传值会让它写入副本，调用方拿不到数据。Gin 的签名接受 `any`，所以传值可能编译通过，但运行时绑定失败或得到零值。

### 6.12.3 在上下文中存指针

```go
c.Set("user", &user)
```

取出：

```go
u, ok := c.Get("user")
if !ok {
    // 不存在
}
user, ok := u.(*User)
if !ok {
    // 类型不对
}
fmt.Println(user.Name)
```

存指针可以让后续 handler 修改同一个用户对象；存值则是快照。选择取决于你是否需要共享修改。

### 6.12.4 GORM 的链式对象

```go
db.Where("age > ?", 18).Order("id DESC").Limit(10).Find(&users)
```

- `db` 是 `*gorm.DB`；
- 每个链式方法返回新的 `*gorm.DB`（内部克隆 Statement）；
- 最终 `Find(&users)` 通过指针写入结果；
- 错误在返回值的 `.Error` 字段。

指针让链式调用可以持续传递同一个数据库会话配置，同时避免复制整个 DB 对象。

### 6.12.5 一张对照表

| 场景 | 写法 | 原因 |
|------|------|------|
| Gin handler | `func(c *gin.Context)` | 共享请求状态 |
| 绑定 JSON | `c.ShouldBindJSON(&req)` | 反射写入 |
| Gin 上下文存值 | `c.Set("user", &user)` | 共享对象 |
| GORM 创建 | `db.Create(&user)` | 回填 ID/时间 |
| GORM 查询单条 | `db.First(&user, id)` | 写入结果 |
| GORM 查询列表 | `db.Find(&users)` | 更新切片头 |
| GORM 指定模型 | `db.Model(&User{})` | 表名/类型信息 |
| 可空字段 | `Age *int` | 区分 NULL 与 0 |
| PATCH 请求 | `Age *int` | 区分未提供与 0 |

## 6.15 本章小结

| 概念 | 一句话解释 | 易错点 |
|------|------------|--------|
| `&x` | 取地址，得到 `*T` | 只能用于可寻址的值 |
| `*p` | 解引用，得到 `T` | nil 指针解引用会 panic |
| `*T` | 指针类型 | 不同类型不能互相赋值 |
| nil 指针 | 未指向任何对象 | 使用前判空 |
| 指针参数 | 修改调用方 | 传的是地址副本 |
| 指针返回 | 可返回局部变量地址 | 编译器负责逃逸 |
| `new(T)` | 返回零值 `*T` | 不能初始化 |
| `&T{}` | 返回可初始化的 `*T` | 业务代码首选 |
| 自动解引用 | `p.Field` = `(*p).Field` | 不可寻址值不能取地址 |
| GORM Create | 回填 ID/时间戳 | 必须传 `&user` |
| GORM Find | 更新切片头 | 必须传 `&users` |
| 指针字段 | 表达 NULL / 未设置 | 使用前判 nil |
| JSON null | nil 指针输出 null | `omitempty` 只省略 nil |
| PATCH | `*T` 区分未提供 | 无法区分显式 null |
| 多级指针 | `**T` | 日常几乎不用 |

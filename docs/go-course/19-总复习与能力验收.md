### 语法与类型（1–5）

**Q1. `var`、`:=`、`=` 有什么区别？**

`var` 可用于包级和函数级，可不赋值（得到零值）；`:=` 只能函数内，必须赋值，左侧至少一个新变量；`=` 只赋值，不声明。

```go
var a int      // 0
b := 1         // 声明 + 推断
var c int = 2  // 声明 + 指定类型
a = b          // 赋值
```

**Q2. 列出常见零值，并说明 `nil` 能用于哪些类型。**

数值 `0`、字符串 `""`、布尔 `false`、指针/切片/map/channel/func/interface 为 `nil`。`nil` 不能赋给 `int`、`string`、`bool`、结构体。

```go
var s []int      // nil，但可以 append
var m map[string]int // nil，读取可以，写入会 panic
```

**Q3. 无类型常量和 `iota` 有什么用？**

无类型常量在使用时按上下文取类型，避免大量转换；`iota` 生成递增枚举。

```go
type Status int

const (
    Pending Status = iota // 0
    Paid                  // 1
    Shipped               // 2
)
```

**Q4. 类型别名与新类型有什么区别？**

`type A = B` 是别名，完全等同；`type A B` 是新类型，底层类型相同但不能直接赋值，必须转换。

```go
type UserID = int   // 别名
type OrderID int    // 新类型
var o OrderID = 1
var i int = int(o)  // 必须转换
```

**Q5. 什么是变量遮蔽？如何排查？**

内层作用域用 `:=` 声明了同名变量，外层变量被遮住：

```go
x := 1
if true {
    x := 2 // 新变量，外层 x 不变
    _ = x
}
fmt.Println(x) // 1
```

排查：注意 `if err := ...`、`for` 内短声明；用 `go vet`、`shadow` 工具；关键变量用不同名字。

### 复合类型与字符串（6–10）

**Q6. 数组和切片有什么区别？**

数组长度固定、是值类型，赋值和传参复制整个数组；切片是「指针 + len + cap」的头部，底层共享数组。

```go
a := [3]int{1, 2, 3}
b := a        // 复制
b[0] = 99
fmt.Println(a[0], b[0]) // 1 99
```

**Q7. 两个切片共享底层数组时，`append` 会发生什么？**

容量足够时写入同一数组；容量不足时扩容，产生新数组，不再共享。

```go
a := []int{1, 2, 3}
b := a[:2]
b = append(b, 99)
fmt.Println(a, b) // [1 2 99] [1 2 99]
```

**Q8. map 的 comma-ok、遍历顺序、并发限制是什么？**

```go
v, ok := m["k"] // key 不存在时 v 是零值，ok 是 false
delete(m, "k")
```

遍历顺序随机；map 并发读写会 panic；key 必须可比较。并发场景用 `sync.RWMutex` 或 `sync.Map`。

**Q9. `len(s)` 和 `range s` 对字符串分别意味着什么？**

`len(s)` 是字节数；`range` 按 UTF-8 解码，返回字节索引和 `rune`；`s[i]` 得到 `byte`。

```go
s := "中文"
fmt.Println(len(s))         // 6
fmt.Println(len([]rune(s))) // 2
for i, r := range s {
    fmt.Println(i, r) // 0 20013 / 3 25991
}
```

**Q10. 大量字符串拼接为什么用 `strings.Builder`？**

字符串不可变，`+=` 每次都分配新字符串，复杂度 O(n²)；`Builder` 内部用 `[]byte` 追加，最后一次性转字符串。

```go
var b strings.Builder
for i := 0; i < 1000; i++ {
    b.WriteString("x")
}
s := b.String()
```

### 结构体、指针、接口（11–15）

**Q11. Go 的嵌入是继承吗？**

不是。嵌入是组合：字段和方法被提升，但本质是「包含一个匿名字段」，没有虚函数表、没有方法重写。

```go
type User struct{ Name string }
type Admin struct {
    User
    Level int
}
a := Admin{User: User{Name: "张三"}, Level: 1}
fmt.Println(a.Name) // 提升字段
```

**Q12. 值接收者和指针接收者有什么区别？**

值接收者拿到副本，修改不影响原值；指针接收者可以修改原值。方法集也不同：`T` 只包含值接收者方法，`*T` 包含两者。

**Q13. 方法集如何影响接口实现？**

```go
type Speaker interface{ Speak() }

type User struct{ Name string }

func (u *User) Speak() { fmt.Println(u.Name) }

var s Speaker = &User{Name: "张三"} // 正确
// var s Speaker = User{}          // 编译错误：User 没有 Speak
```

指针接收者的方法只有 `*User` 满足接口。

**Q14. 什么是「nil 接口」陷阱？**

接口值由「动态类型 + 动态值」组成。只有两者都为 nil，接口才等于 nil。

```go
type MyErr struct{}
func (e *MyErr) Error() string { return "my" }

var p *MyErr
var err error = p
fmt.Println(err == nil) // false：动态类型是 *MyErr，值是 nil
```

**Q15. 类型断言和 `type switch` 怎么用？**

```go
v, ok := x.(string) // 安全断言

switch v := x.(type) {
case int:
    fmt.Println("int", v)
case string:
    fmt.Println("string", v)
default:
    fmt.Println("other", v)
}
```

`x.(T)` 失败会 panic；不确定时用 comma-ok。

### 函数、错误、泛型（16–20）

**Q16. `defer` 的执行顺序和参数求值时机？**

后进先出；参数在 `defer` 语句处立即求值；命名返回值可被 `defer` 修改。

```go
func f() (n int) {
    defer func() { n *= 2 }()
    return 3
}
// 返回 6
```

**Q17. `recover` 什么时候有效？**

只在 `defer` 的函数中直接调用有效；它能捕获同一 goroutine 的 panic。子 goroutine 的 panic 必须在子 goroutine 内 recover，否则进程崩溃。

**Q18. 闭包捕获的是值还是变量？Go 1.22 有什么变化？**

捕获变量本身。Go 1.22 起，`for` 每轮迭代创建新变量；旧版本三个闭包会都打印最后一个值。行为取决于 `go.mod` 的 `go` 版本。

```go
var fs []func()
for i := 0; i < 3; i++ {
    fs = append(fs, func() { fmt.Println(i) })
}
for _, f := range fs {
    f() // go 1.22+: 0 1 2；go 1.21: 3 3 3
}
```

**Q19. `errors.Is` 和 `errors.As` 的区别？**

`Is` 判断错误链中是否包含目标哨兵错误；`As` 把错误链中某类错误提取到目标变量。

```go
if errors.Is(err, gorm.ErrRecordNotFound) { /* 404 */ }

var ve *ValidationError
if errors.As(err, &ve) {
    fmt.Println(ve.Field)
}
```

**Q20. 如何设计哨兵错误和自定义错误？**

哨兵错误用 `errors.New` 定义包级变量；自定义错误实现 `Error() string`，需要携带字段时用 struct。

```go
var ErrNotFound = errors.New("not found")

type ValidationError struct{ Field string }
func (e *ValidationError) Error() string {
    return "invalid field: " + e.Field
}
```

GORM 的 `gorm.ErrRecordNotFound` 就是哨兵错误，配合 `errors.Is` 使用。

**Q21. 泛型的基本写法与边界？**

```go
func Map[T, U any](s []T, f func(T) U) []U {
    out := make([]U, 0, len(s))
    for _, v := range s {
        out = append(out, f(v))
    }
    return out
}
```

约束可以是 `any`、`comparable`、联合类型 `int | int64`、`~int`（底层类型）。方法不能额外声明类型参数；只有一两种类型时不要强行泛型。

### 并发（22–27）

**Q22. 如何启动并等待 goroutine？**

```go
var wg sync.WaitGroup
wg.Add(2)

go func() { defer wg.Done(); fmt.Println("A") }()
go func() { defer wg.Done(); fmt.Println("B") }()

wg.Wait()
```

主 goroutine 退出会结束整个程序，不会等待其他 goroutine。

**Q23. 无缓冲与有缓冲 channel 的区别？**

无缓冲发送和接收必须同时就绪（同步握手）；有缓冲在容量未满时发送不阻塞。`close` 只能由发送方调用，关闭后仍可接收剩余值，`v, ok` 的 `ok` 变 false。向已关闭 channel 发送会 panic。

**Q24. 如何用 `select` 实现超时？**

```go
select {
case v := <-ch:
    fmt.Println(v)
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

循环中频繁使用 `time.After` 会积累计时器，长循环可用 `time.NewTimer` 并 `Reset`。

**Q25. `context` 的常用函数与使用规范？**

`Background`/`TODO` 作根；`WithCancel`、`WithTimeout`、`WithDeadline` 派生可取消 context；`WithValue` 只放请求级元数据。context 作为函数第一个参数，不要存进 struct；创建后一定调用 `cancel`。

**Q26. `Mutex`、`RWMutex`、`atomic` 怎么选？**

`Mutex` 保护临界区；`RWMutex` 适合读多写少；`atomic` 适合单个计数器的增减。用 `go test -race` 检测竞争。不要复制已使用的 `Mutex`。

**Q27. goroutine 泄漏的常见原因？**

- 向无人接收的 channel 发送；
- 从无人发送的 channel 接收；
- 循环 goroutine 没有退出条件；
- `Ticker` 没有 `Stop`；
- 请求取消后仍阻塞在 I/O。

修复：用 `context` 传递取消，`select` 监听 `ctx.Done()`，确保 channel 有发送方/接收方，`defer ticker.Stop()`。

### 标准库（28–30）

**Q28. JSON 编解码有哪些高频规则？**

字段必须导出；用 `json:"name"` 改键名；`omitempty` 对零值（`0`、`""`、`false`、nil）省略；需要区分「零值」和「未设置」时用指针字段；`time.Time` 默认 RFC3339；解码到 `interface{}` 时数字是 `float64`。

```go
type Req struct {
    Name string `json:"name"`
    Age  *int   `json:"age,omitempty"`
}
```

**Q29. `net/http` 的 Handler 与中间件本质是什么？**

```go
type Handler interface {
    ServeHTTP(http.ResponseWriter, *http.Request)
}
type HandlerFunc func(http.ResponseWriter, *http.Request)
func (f HandlerFunc) ServeHTTP(w http.ResponseWriter, r *http.Request) { f(w, r) }
```

中间件就是「接收 Handler，返回 Handler」的函数，在调用 `next.ServeHTTP` 前后做事情。请求上下文用 `r.Context()`，服务端要配置超时与 `Shutdown`。

**Q30. `database/sql` 的常用方法与连接池参数？**

`sql.Open` 只创建池，不连接；`Ping` 验证。`Query` 多行、`QueryRow` 单行、`Exec` 写入；结果用 `Scan` 读取。优先用带 `Context` 的版本。

```go
sqlDB, _ := sql.Open("mysql", dsn)

sqlDB.SetMaxOpenConns(100)
sqlDB.SetMaxIdleConns(10)
sqlDB.SetConnMaxLifetime(time.Hour)
sqlDB.SetConnMaxIdleTime(10 * time.Minute)
```

GORM 底层就是 `database/sql`，`db.DB()` 可取回 `*sql.DB` 配置连接池。

### 19.3.2 Gin 文档题

**题 1：`c.ShouldBindJSON` 与 `c.BindJSON` 的区别？**

`BindJSON` 在失败时自动写 400 并 `Abort`；`ShouldBindJSON` 只返回错误，不写响应，适合自己控制错误格式。

```go
var req CreateUserReq
if err := c.ShouldBindJSON(&req); err != nil {
    c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
    return
}
```

**题 2：`c.Next()` 和 `c.Abort()` 分别做什么？**

`c.Next()` 执行后续 handler，返回后继续当前中间件剩余代码；`c.Abort()` 阻止后续 handler，但**不会**中断当前函数，仍需 `return`。`AbortWithStatusJSON` 等于 `Abort` + 写响应。

**题 3：中间件的执行顺序？**

注册顺序即进入顺序，退出顺序相反：

```text
A 进入 → B 进入 → handler → B 退出 → A 退出
```

### 19.3.3 GORM 文档题

**题 1：`Updates`、`Update`、`Save` 怎么选？**

- `Updates(struct)`：部分更新，零值被忽略；
- `Updates(map)` / `Update`：需要更新零值时用；
- `Save`：全量保存，零值也会写入；
- `UpdateColumn`：跳过钩子、不更新时间。

**题 2：`Preload` 与 `Joins` 怎么选？**

`Preload` 用额外查询加载关联，适合 HasMany、列表页；`Joins` 用 JOIN 一次查完，适合 BelongsTo/HasOne 以及按关联表字段过滤。HasMany 用 `Joins` 容易出现重复行和字段覆盖问题。

**题 3：`Session` 的 `NewDB`、`DryRun`、`SkipHooks` 分别做什么？**

`NewDB` 清空已有条件；`DryRun` 只生成 SQL 不执行；`SkipHooks` 跳过钩子。`db.Session(&gorm.Session{NewDB: true})` 常用于需要干净查询起点的场景。

**题 4：`Transaction` 的提交与回滚规则？**

回调返回 `nil` 提交；返回 `error` 回滚；`panic` 回滚并继续抛出。回调内部必须用参数 `tx`，不能用外层 `db`。

### 题目 4：Gin 中间件顺序

```go
r := gin.New()
r.Use(func(c *gin.Context) {
    fmt.Print("A1 ")
    c.Next()
    fmt.Print("A2 ")
})
r.Use(func(c *gin.Context) {
    fmt.Print("B1 ")
    c.Next()
    fmt.Print("B2 ")
})
r.GET("/", func(c *gin.Context) {
    fmt.Print("H ")
    c.JSON(200, gin.H{"ok": true})
})
```

请求 `/` 时输出什么？

### 题目 5：GORM 零值更新

```go
type User struct {
    ID   uint
    Name string
    Age  int
}

db.AutoMigrate(&User{})
db.Create(&User{Name: "张三", Age: 20})
db.Create(&User{Name: "李四", Age: 30})

var u User
db.First(&u, 1)
db.Model(&u).Updates(User{Age: 0})
db.First(&u, 1)
fmt.Println(u.Age)
```

### 答案与解释

1. 输出 `[1 2 99] [1 2 99]`。`b` 的容量是 3，`append` 直接写入底层数组索引 2。
2. 输出 `6`。`return 3` 先赋给命名返回值 `n`，`defer` 再执行 `n *= 2`。
3. 输出 `false`。接口的动态类型是 `*MyErr`，动态值是 nil，接口本身不为 nil。
4. 输出 `A1 B1 H B2 A2 `。进入顺序 A→B→H，退出顺序 B→A。
5. 输出 `20`。`Updates` 接收 struct，`Age: 0` 是零值，被忽略。

## 19.6 常见误区总结

| 误区 | 正确理解 |
|------|----------|
| `nil` 切片和空切片一样 | JSON 分别是 `null` 和 `[]`；`len` 都是 0 |
| map 遍历顺序稳定 | Go 故意随机化，需要顺序先排序 key |
| `range` 的 value 能改原切片 | value 是副本，要用索引 |
| 闭包捕获的是值 | 捕获变量本身；Go 1.22 每轮新建 |
| 指针接收者一定更好 | 小对象、不可变值用值接收者更清晰 |
| 接口为 nil 就是里面指针为 nil | 动态类型非 nil 时接口不为 nil |
| `err == 哨兵错误` 可靠 | 用 `errors.Is`，错误可能被包装 |
| `recover` 随处可调用 | 只在 defer 中直接调用有效 |
| 子 goroutine panic 主 goroutine 能 recover | 不能，必须各自 recover |
| context 可以存进 struct | 应作为第一个参数显式传递 |
| `time.After` 在循环里没问题 | 会积累计时器，长循环用 Timer |
| `sql.Open` 会建立连接 | 只创建池，`Ping` 才验证 |
| 连接池越大越好 | 受数据库上限约束，过大反而抖动 |
| `c.JSON` 会终止 handler | 不会，后面代码仍执行，需 `return` |
| `c.Abort()` 会终止当前函数 | 不会，只阻止后续 handler |
| `ShouldBindJSON` 自动写 400 | 不会，`BindJSON` 才会 |
| GORM 的 `Find` 查不到报错 | 不报错，返回空切片 |
| GORM struct 更新会写零值 | 不会，零值被忽略 |
| GORM 删除就是物理删除 | 有 `DeletedAt` 时是软删除 |
| `Preload` 越多越好 | 关联过多会放大查询与内存 |
| 事务里可以用外层 `db` | 必须用 `tx`，否则不在事务内 |
| `Save` 等价于 `Updates` | `Save` 全量更新，包含零值 |
| 读了文档就等于会了 | 必须手敲、运行、改错、复述 |

## 19.7 综合实战验收

完成一个「用户 + 订单」迷你 API，作为课程结业项目。

### 19.7.1 功能要求

1. `POST /users` 创建用户，校验邮箱唯一；
2. `GET /users/:id` 查询用户，查不到返回 404；
3. `GET /users?page=1&size=10` 分页列表；
4. `POST /orders` 创建订单，扣减库存（事务）；
5. `GET /users/:id/orders` 返回用户订单（Preload）；
6. 统一错误响应格式；
7. 请求日志中间件 + Recovery；
8. 优雅关闭；
9. 至少 3 个 handler 测试；
10. README 写明启动方式、接口示例、设计取舍。

### 19.7.2 技术约束

- Gin v1.9+，GORM v2；
- repository 层接收 `context.Context`；
- 所有数据库操作 `WithContext`；
- 事务内部只用 `tx`；
- 不把 `*gorm.DB` 放进 `gin.Context`；
- 不拼接 SQL；
- 连接池显式配置；
- 错误用 `errors.Is/As` 判断，不比较字符串。

### 19.7.3 验收清单

- [ ] 项目能一条命令启动；

- [ ] 分页参数非法时返回 400；
- [ ] 测试可重复运行，不依赖本地数据库状态；
- [ ] 代码分层清晰，handler 不直接写 SQL；
- [ ] README 能让陌生人独立跑起来。

## 19.9 本章小结

### 19.9.1 你学到的三件事

1. **看懂类型**：签名里的 `*`、`...`、`interface{}`、`[T any]`、`func(*Context)` 不再陌生。
2. **写对代码**：知道零值、切片共享、nil 接口、defer、context、事务边界在哪里出问题。
3. **查得动文档**：从 pkg.go.dev 到源码，从示例到边界，能独立补齐陌生 API。

### 19.9.2 从「学过」到「会用」

| 学过 | 会用 |
|------|------|
| 能看懂示例 | 能改示例解决自己的问题 |
| 能背 API | 能查签名并判断边界 |
| 能写单文件 | 能分层、测试、部署 |
| 能跑通 | 能排错、能解释为什么 |

### 19.9.3 最后一条建议

不要追求「把 Go 全部学完」。Go 的日常业务面并不宽：类型、切片、map、结构体、指针、接口、错误、goroutine、channel、context、JSON、HTTP、SQL，加上 Gin/GORM，已经覆盖绝大多数工作。

真正拉开差距的，是**遇到陌生 API 时知道怎么查、怎么验证、怎么避开坑**。这门课的训练目标，就是把这件事变成习惯。

## 3.1 `if`：条件分支

### 3.1.1 基本写法

```go
package main

import "fmt"

func main() {
    x := 10

    if x > 0 {
        fmt.Println("正数")
    } else if x < 0 {
        fmt.Println("负数")
    } else {
        fmt.Println("零")
    }
}
```

输出：

```
正数
```

要点：

- `if` 后面**不需要括号**；
- 条件必须是 `bool`，不能是数字或字符串；
- 左大括号必须和 `if` 在同一行（第 01 章讲过原因）。

`if (x > 0) { }` 语法上通常也能编译，但 Go 的惯用写法不加括号，`gofmt` 也不会替你删掉。建议直接不写。

---

### 3.1.2 条件必须是布尔值

TypeScript 里很多值可以当作「真值」：

```ts
if (1) { }        // 合法
if ("hello") { }  // 合法
```

Go 不允许：

```go
if 1 { }        // 编译错误
if "hello" { }  // 编译错误
```

必须写成明确的比较：

```go
if x != 0 { }
if s != "" { }
```

---

### 3.1.3 带初始化语句的 `if`

Go 允许在 `if` 里先执行一条简单语句，再判断：

```go
if n, err := strconv.Atoi("123"); err == nil {
    fmt.Println("转换成功：", n)
} else {
    fmt.Println("转换失败：", err)
}
```

变量 `n` 和 `err` 的作用域包括整个 `if-else`：

```go
if x := 10; x > 5 {
    fmt.Println(x) // 10
} else {
    fmt.Println(x) // 也能访问
}
```

这种写法在实际项目中非常常见，尤其是错误处理：

```go
if err := doSomething(); err != nil {
    return err
}
```

> 注意：`err` 的作用域只在 `if` 内，不会污染外面的变量。但也要小心它遮蔽外层的同名变量（第 02 章 2.7 节）。

---

### 3.1.4 Go 没有三元运算符

TypeScript：

```ts
const label = n > 0 ? "正数" : "非正数"
```

Go 没有 `?:`，只能写 `if-else`：

```go
var label string
if n > 0 {
    label = "正数"
} else {
    label = "非正数"
}
```

简单场景也可以抽成小函数：

```go
func positiveLabel(n int) string {
    if n > 0 {
        return "正数"
    }
    return "非正数"
}
```

## 3.2 `for`：唯一的循环

Go 只有 `for` 一种循环关键字，没有 `while`、`do-while`。

### 3.2.1 三种形态

**形态一：经典三段式**

```go
for i := 0; i < 5; i++ {
    fmt.Println(i)
}
```

输出：

```
0
1
2
3
4
```

**形态二：条件式（替代 `while`）**

```go
i := 0
for i < 5 {
    fmt.Println(i)
    i++
}
```

**形态三：无限循环**

```go
for {
    // 必须用 break / return / panic 退出
}
```

`for {}` 等价于其他语言的 `while (true) {}`。

---

### 3.2.2 `break` 与 `continue`

```go
for i := 0; i < 10; i++ {
    if i == 5 {
        break // 跳出整个循环
    }
    if i%2 == 0 {
        continue // 跳过本次，进入下一次
    }
    fmt.Println(i)
}
```

输出：

```
1
3
```

---

### 3.2.3 标签：跳出多层循环

```go
outer:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if j == 1 {
            continue outer // 继续外层循环的下一次
        }
        if i == 2 {
            break outer // 直接跳出外层循环
        }
        fmt.Println(i, j)
    }
}
```

标签的常见用途：

- `break 标签`：跳出指定外层循环；
- `continue 标签`：继续指定外层循环；
- `goto 标签`：跳到指定位置（少用）。

---

### 3.2.4 `goto`（了解，不推荐）

```go
i := 0
loop:
if i < 3 {
    fmt.Println(i)
    i++
    goto loop
}
```

Go 的 `goto` 有约束：**不能跳过变量声明**。

```go
goto L
x := 1
L:
fmt.Println(x) // 编译错误：goto L jumps over declaration of x
```

业务代码里几乎不用 `goto`。看到它时知道含义即可。

## 3.3 `range`：遍历

### 3.3.1 遍历切片

```go
nums := []int{10, 20, 30}

for i, v := range nums {
    fmt.Println(i, v)
}
```

输出：

```
0 10
1 20
2 30
```

- `i` 是索引；
- `v` 是元素的**副本**。

只关心索引：

```go
for i := range nums {
    fmt.Println(i)
}
```

只关心值：

```go
for _, v := range nums {
    fmt.Println(v)
}
```

---

### 3.3.2 修改 range 的值不会修改原切片

```go
nums := []int{1, 2, 3}

for _, v := range nums {
    v *= 10
}

fmt.Println(nums) // [1 2 3]，没有变化
```

原因：`v` 是元素副本。

想修改原切片，用索引：

```go
for i := range nums {
    nums[i] *= 10
}

fmt.Println(nums) // [10 20 30]
```

---

### 3.3.3 遍历 map

```go
m := map[string]int{
    "apple":  1,
    "banana": 2,
    "cherry": 3,
}

for k, v := range m {
    fmt.Println(k, v)
}
```

关键点：**map 的遍历顺序是随机的**。每次运行顺序可能不同。

如果需要稳定顺序，先取出 key 排序：

```go
keys := make([]string, 0, len(m))
for k := range m {
    keys = append(keys, k)
}
sort.Strings(keys)

for _, k := range keys {
    fmt.Println(k, m[k])
}
```

> 不要依赖 map 的遍历顺序写业务逻辑。

---

### 3.3.4 遍历字符串

```go
for i, r := range "Go中文" {
    fmt.Println(i, r, string(r))
}
```

输出：

```
0 71 G
1 111 o
2 20013 中
5 25991 文
```

解释：

- `i` 是**字节索引**，不是字符序号；
- `r` 是 `rune`（Unicode 码点）；
- 中文一个字通常占 3 个 UTF-8 字节，所以「中」从索引 2 开始，「文」从索引 5 开始。

如果按字节遍历：

```go
s := "Go中文"
for i := 0; i < len(s); i++ {
    fmt.Println(i, s[i]) // s[i] 是 byte
}
```

输出的是每个字节的数值，不是完整字符。

---

### 3.3.5 遍历 channel

```go
ch := make(chan int, 2)
ch <- 1
ch <- 2
close(ch)

for v := range ch {
    fmt.Println(v)
}
```

输出：

```
1
2
```

`range` channel 会一直读到 channel 关闭为止。第 11 章展开。

---

### 3.3.6 遍历整数（Go 1.22+）

```go
for i := range 3 {
    fmt.Println(i)
}
```

输出：

```
0
1
2
```

等价于 `for i := 0; i < 3; i++`。这是 Go 1.22 新增的写法，要求模块的 `go.mod` 声明 `go 1.22` 或更高。

---

### 3.3.7 循环变量语义（Go 1.22 的重要变化）

先看一段代码：

```go
var funcs []func()

for i := 0; i < 3; i++ {
    funcs = append(funcs, func() {
        fmt.Println(i)
    })
}

for _, f := range funcs {
    f()
}
```

- **Go 1.22 及以上（go.mod 声明 go 1.22+）**：输出 `0 1 2`；
- **Go 1.21 及以下（或 go.mod 声明 go 1.21）**：输出 `3 3 3`。

原因：旧版本里，循环变量 `i` 在所有迭代中复用同一个变量；闭包捕获的是这个变量本身，循环结束后它的值是 3。

Go 1.22 改为每次迭代创建新的循环变量，所以每个闭包捕获到各自的值。

> **注意**：这个行为由 `go.mod` 里的 `go` 版本决定。如果模块声明 `go 1.21`，即使你用 Go 1.22 的工具链，仍然是旧语义。

---

### 3.3.8 `range` 的版本提示

| 遍历对象 | 说明 |
|----------|------|
| 数组、切片 | 索引 + 元素副本 |
| map | key + value，顺序随机 |
| string | 字节索引 + rune |
| channel | 直到 channel 关闭 |
| 整数（Go 1.22+） | 0 到 n-1 |
| 函数（Go 1.23+，了解） | 迭代器协议，本课程不展开 |

## 3.4 `switch`：多分支

### 3.4.1 表达式 switch

```go
switch x {
case 1:
    fmt.Println("一")
case 2, 3:
    fmt.Println("二或三")
default:
    fmt.Println("其他")
}
```

要点：

- `case` 可以写多个值，用逗号分隔；
- **不需要写 `break`**，每个 `case` 执行完自动结束；
- `default` 可选；
- 重复的 `case` 值是编译错误。

---

### 3.4.2 无表达式 switch

相当于更清晰的 `if-else` 链：

```go
switch {
case x < 0:
    fmt.Println("负数")
case x == 0:
    fmt.Println("零")
default:
    fmt.Println("正数")
}
```

---

### 3.4.3 `fallthrough`：继续执行下一个 case

```go
switch x {
case 1:
    fmt.Println("一")
    fallthrough
case 2:
    fmt.Println("二")
default:
    fmt.Println("其他")
}
```

如果 `x == 1`，输出：

```
一
二
```

规则：

- `fallthrough` 必须是 `case` 里的最后一条语句；
- 不能用在最后一个 `case`；
- 不能用在 `type switch` 中。

---

### 3.4.4 `switch` 里的 `break`

`switch` 里的 `break` 只会跳出 `switch`，不会跳出外层循环：

```go
for i := 0; i < 3; i++ {
    switch i {
    case 1:
        break // 只跳出 switch，循环继续
    }
    fmt.Println("loop", i)
}
```

如果要从 `switch` 里跳出外层循环，用标签：

```go
outer:
for i := 0; i < 3; i++ {
    switch i {
    case 2:
        break outer
    }
}
```

---

### 3.4.5 带初始化语句的 switch

```go
switch n := len(s); n {
case 0:
    fmt.Println("空字符串")
case 1:
    fmt.Println("一个字节")
default:
    fmt.Println("多个字节")
}
```

---

### 3.4.6 `type switch`（预告）

```go
switch v := x.(type) {
case int:
    fmt.Println("int:", v)
case string:
    fmt.Println("string:", v)
default:
    fmt.Println("其他类型")
}
```

这是接口相关的语法，第 07 章详细讲。现在知道 `switch` 可以按类型分支即可。

## 3.5 函数

### 3.5.1 基本定义

```go
func add(a, b int) int {
    return a + b
}
```

- `func` 关键字；
- 函数名 `add`；
- 参数 `a, b int`：两个参数都是 `int`；
- 返回值 `int`；
- 函数体。

调用：

```go
sum := add(3, 5)
fmt.Println(sum) // 8
```

---

### 3.5.2 Go 函数没有重载、默认参数、可选参数

TypeScript 可以：

```ts
function greet(name: string, greeting = "Hello"): string { ... }
```

Go 不支持：

- 不能同名函数不同参数（没有重载）；
- 不能给参数默认值；
- 不能声明可选参数。

替代方案：

**用可变参数：**

```go
func greet(name string, greetings ...string) string {
    greeting := "Hello"
    if len(greetings) > 0 {
        greeting = greetings[0]
    }
    return greeting + ", " + name
}
```

**用选项结构体：**

```go
type GreetOptions struct {
    Greeting string
    Punctuation string
}

func greet(name string, opts GreetOptions) string {
    if opts.Greeting == "" {
        opts.Greeting = "Hello"
    }
    return opts.Greeting + ", " + name + opts.Punctuation
}
```

**用 Functional Options（见 3.8.5）：**

适合参数很多、大部分可选的场景。

---

### 3.5.3 多返回值

```go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("除数不能为 0")
    }
    return a / b, nil
}
```

调用：

```go
result, err := divide(10, 2)
if err != nil {
    fmt.Println("出错：", err)
    return
}
fmt.Println(result) // 5
```

Go 的错误处理惯例：

- 最后一个返回值通常是 `error`；
- 成功时 `error` 为 `nil`；
- 调用方必须显式检查。

---

### 3.5.4 命名返回值

```go
func divmod(a, b int) (q, r int) {
    q = a / b
    r = a % b
    return
}
```

`return` 后面不写值，叫「裸返回」。

优点：短函数里可读性好。

缺点：长函数里裸返回会让人找不到返回了什么，**不推荐**。

命名返回值通常用于：

- 需要在 `defer` 中修改返回值；
- 文档需要说明每个返回值的含义。

---

### 3.5.5 可变参数

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}
```

调用：

```go
fmt.Println(sum(1, 2, 3)) // 6
fmt.Println(sum())        // 0

nums := []int{1, 2, 3, 4}
fmt.Println(sum(nums...)) // 10
```

规则：

- `...T` 必须放在参数列表最后；
- 一个函数只能有一个可变参数；
- 在函数内部，`nums` 的类型是 `[]int`。

---

### 3.5.6 函数是一等公民

函数可以赋值给变量、作为参数、作为返回值。

```go
func add(a, b int) int {
    return a + b
}

func main() {
    var f func(int, int) int = add
    fmt.Println(f(1, 2)) // 3
}
```

函数类型：

```go
type BinOp func(int, int) int

func apply(a, b int, op BinOp) int {
    return op(a, b)
}

fmt.Println(apply(1, 2, add)) // 3
```

---

### 3.5.7 匿名函数与闭包

匿名函数：

```go
double := func(x int) int {
    return x * 2
}

fmt.Println(double(5)) // 10
```

闭包：函数捕获了外部变量。

```go
func counter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

func main() {
    next := counter()
    fmt.Println(next()) // 1
    fmt.Println(next()) // 2
    fmt.Println(next()) // 3
}
```

`count` 被闭包捕获，生命周期延长到闭包不再使用为止。

多个闭包可以共享同一个捕获变量：

```go
func pair() (func() int, func() int) {
    n := 0
    inc := func() int {
        n++
        return n
    }
    get := func() int {
        return n
    }
    return inc, get
}
```

---

### 3.5.8 递归

```go
func factorial(n int) int {
    if n <= 1 {
        return 1
    }
    return n * factorial(n-1)
}
```

递归必须有终止条件，否则会栈溢出。

---

### 3.5.9 命名函数不能嵌套声明

Go 不允许在函数内部再声明一个命名函数：

```go
func main() {
    func helper() { // 编译错误
    }
}
```

如果需要在函数内定义函数，用函数字面量：

```go
func main() {
    helper := func() {
        fmt.Println("hello")
    }
    helper()
}
```

---

### 3.5.10 函数的导出

首字母大写才能被其他包调用：

```go
func Add(a, b int) int { return a + b } // 导出
func add(a, b int) int { return a + b } // 包内私有
```

## 3.6 `defer`：延迟执行

### 3.6.1 基本行为

`defer` 语句会把函数调用推迟到**当前函数返回之前**执行。

```go
func main() {
    defer fmt.Println("最后执行")
    fmt.Println("先执行")
}
```

输出：

```
先执行
最后执行
```

---

### 3.6.2 后进先出（LIFO）

```go
func main() {
    defer fmt.Println("A")
    defer fmt.Println("B")
    defer fmt.Println("C")

    fmt.Println("main")
}
```

输出：

```
main
C
B
A
```

多个 `defer` 按声明的**相反顺序**执行。

---

### 3.6.3 参数在 `defer` 语句处求值

```go
func main() {
    x := 1

    defer fmt.Println("defer x =", x)

    x = 2
    fmt.Println("main x =", x)
}
```

输出：

```
main x = 2
defer x = 1
```

虽然 `defer` 在最后执行，但参数 `x` 在 `defer` 语句出现时就已经求值并保存为 1。

如果希望延迟读取最新值，用闭包：

```go
defer func() {
    fmt.Println("defer x =", x) // 读取的是执行时的 x
}()
```

---

### 3.6.4 `defer` 与命名返回值

```go
func f() (n int) {
    defer func() {
        n++
    }()
    return 1
}
```

返回值是 `2`。

执行顺序：

1. `return 1` 把 `n` 设为 1；
2. `defer` 执行 `n++`，`n` 变成 2；
3. 函数返回 `n`，即 2。

这个特性常用于：

- 记录函数耗时；
- 捕获 panic 并修改返回的 error。

```go
func safeDivide(a, b int) (result int, err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("panic: %v", r)
        }
    }()

    return a / b, nil
}
```

---

### 3.6.5 `defer` 的常见用途

**关闭文件：**

```go
f, err := os.Open("data.txt")
if err != nil {
    return err
}
defer f.Close()
```

**释放锁：**

```go
mu.Lock()
defer mu.Unlock()
```

**记录耗时：**

```go
start := time.Now()
defer func() {
    fmt.Println("耗时：", time.Since(start))
}()
```

**捕获 panic：**

```go
defer func() {
    if r := recover(); r != nil {
        fmt.Println("recovered:", r)
    }
}()
```

---

### 3.6.6 `defer` 在循环里的坑

```go
for _, name := range files {
    f, err := os.Open(name)
    if err != nil {
        return err
    }
    defer f.Close() // 所有文件都要等到函数结束才关闭
}
```

问题：如果文件很多，文件描述符会一直占用，可能耗尽。

修复：把循环体抽成函数：

```go
func processFile(name string) error {
    f, err := os.Open(name)
    if err != nil {
        return err
    }
    defer f.Close()

    // 使用 f
    return nil
}

for _, name := range files {
    if err := processFile(name); err != nil {
        return err
    }
}
```

---

### 3.6.7 `defer` 不会在 `os.Exit` 时执行

```go
func main() {
    defer fmt.Println("不会执行")
    os.Exit(1)
}
```

`os.Exit` 直接终止进程，不会执行任何 `defer`。

---

### 3.6.8 panic 时 `defer` 会执行

```go
func main() {
    defer fmt.Println("会执行")
    panic("boom")
}
```

输出：

```
会执行
panic: boom
...
```

`panic` 会触发当前 goroutine 的 `defer` 链，然后程序崩溃（除非被 `recover`）。

---

## 3.7 `panic` 与 `recover`

### 3.7.1 `panic` 是什么

`panic` 会立即中断当前函数的正常执行，开始执行 `defer`，然后向上传播，直到程序崩溃。

```go
func main() {
    fmt.Println("before")
    panic("something bad")
    fmt.Println("after") // 不会执行
}
```

输出：

```
before
panic: something bad

goroutine 1 [running]:
...
```

---

### 3.7.2 `recover` 捕获 panic

`recover` 只能在 `defer` 的函数中**直接调用**，才能捕获 panic。

```go
func safeDivide(a, b int) (result int, err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("panic: %v", r)
        }
    }()

    return a / b, nil
}

func main() {
    result, err := safeDivide(10, 0)
    fmt.Println(result, err) // 0 panic: runtime error: integer divide by zero
}
```

要点：

- `recover()` 返回 `any`；
- 没有 panic 时返回 `nil`；
- 在 `defer` 外调用 `recover()` 返回 `nil`；
- 必须在 `defer` 的函数里直接调用，间接调用无效。

---

### 3.7.3 重新抛出 panic

```go
defer func() {
    if r := recover(); r != nil {
        fmt.Println("记录日志：", r)
        panic(r) // 继续向上抛
    }
}()
```

适合：记录日志后，仍然让上层决定如何处理。

---

### 3.7.4 panic 不能被其他 goroutine 捕获

```go
func main() {
    defer func() {
        fmt.Println("main recover:", recover())
    }()

    go func() {
        panic("goroutine panic")
    }()

    time.Sleep(time.Second)
}
```

结果：程序崩溃，`main` 的 `recover` 捕获不到。

原因：`recover` 只对**同一个 goroutine** 的 panic 有效。每个 goroutine 要自己处理自己的 panic。

---

### 3.7.5 什么时候用 panic

适合：

- 程序无法继续运行的严重错误（配置缺失、初始化失败）；
- 程序员错误（不可能发生的情况）；
- `main` 启动阶段。

不适合：

- 普通业务错误（用户不存在、参数不合法）；
- 库代码中的可预期错误。

普通错误应该返回 `error`：

```go
func findUser(id int) (*User, error) {
    if id <= 0 {
        return nil, fmt.Errorf("无效的用户 ID: %d", id)
    }
    // ...
}
```

> 经验法则：**能返回 error 的地方，不要 panic。** `panic` 是最后手段。

## 3.8 值传递语义

### 3.8.1 Go 只有值传递

Go 的函数参数都是**值拷贝**。传入什么，函数里拿到的就是它的副本。

```go
func modify(n int) {
    n = 100
}

func main() {
    x := 1
    modify(x)
    fmt.Println(x) // 1
}
```

---

### 3.8.2 结构体也是值拷贝

```go
type Point struct {
    X, Y int
}

func move(p Point) {
    p.X++
}

func main() {
    p := Point{X: 1, Y: 2}
    move(p)
    fmt.Println(p.X) // 1
}
```

想修改原结构体，传指针：

```go
func movePtr(p *Point) {
    p.X++
}

movePtr(&p)
fmt.Println(p.X) // 2
```

---

### 3.8.3 切片：复制的是切片头

切片内部包含三个部分：

- 指向底层数组的指针；
- 长度 `len`；
- 容量 `cap`。

传参时复制的是这三个字段，底层数组仍然共享。

```go
func modifySlice(s []int) {
    s[0] = 100
}

func main() {
    nums := []int{1, 2, 3}
    modifySlice(nums)
    fmt.Println(nums) // [100 2 3]
}
```

修改元素会影响调用方。

但在函数内 `append` 不一定会影响调用方的长度：

```go
func appendSlice(s []int) {
    s = append(s, 4)
    fmt.Println("函数内:", s) // [1 2 3 4]
}

func main() {
    nums := []int{1, 2, 3}
    appendSlice(nums)
    fmt.Println("函数外:", nums) // [1 2 3]
}
```

因为 `append` 可能扩容，生成新的底层数组；即使没有扩容，函数内 `s` 的 `len` 变了，调用方的 `len` 仍然是 3。

---

### 3.8.4 map 和 channel 是引用语义

```go
func set(m map[string]int) {
    m["a"] = 1
}

func main() {
    m := make(map[string]int)
    set(m)
    fmt.Println(m) // map[a:1]
}
```

map 变量内部指向运行时结构，复制 map 变量复制的是这个引用，修改内容会影响调用方。

channel 同理。

---

### 3.8.5 闭包捕获的是变量

```go
func main() {
    x := 1

    f := func() {
        fmt.Println(x)
    }

    x = 2
    f() // 2
}
```

闭包捕获的是变量本身，不是声明时的副本。

---

### 3.8.6 值传递总结

| 类型 | 传参复制的内容 | 修改是否影响调用方 |
|------|----------------|--------------------|
| `int`、`string`、`bool` | 值 | 否 |
| 数组 | 整个数组 | 否 |
| 结构体 | 整个结构体 | 否（除非含指针/引用字段） |
| 指针 | 地址 | 通过指针修改会影响 |
| 切片 | 切片头（指针、len、cap） | 修改元素会；`append` 长度不一定 |
| map | 引用 | 会 |
| channel | 引用 | 会 |
| 函数值 | 函数引用 | 不适用 |

> 这就是为什么 GORM 的方法几乎都要求传指针：它需要修改你传入的结构体（回填 ID、写入查询结果）。

---

## 3.9 函数设计实践

### 3.9.1 早返回，减少嵌套

不推荐：

```go
func process(user *User) error {
    if user != nil {
        if user.Name != "" {
            if user.Age > 0 {
                // 业务逻辑
                return nil
            }
        }
    }
    return fmt.Errorf("invalid user")
}
```

推荐：

```go
func process(user *User) error {
    if user == nil {
        return fmt.Errorf("user is nil")
    }
    if user.Name == "" {
        return fmt.Errorf("name is empty")
    }
    if user.Age <= 0 {
        return fmt.Errorf("invalid age")
    }

    // 业务逻辑
    return nil
}
```

---

### 3.9.2 `error` 放最后一个返回值

```go
func GetUser(id int) (*User, error)
```

这是 Go 的通用惯例，几乎所有标准库和框架都遵守。

---

### 3.9.3 `context.Context` 放第一个参数

涉及 I/O、网络、数据库的函数，通常把 `context.Context` 放在第一个参数：

```go
func GetUser(ctx context.Context, id int) (*User, error)
```

第 11 章展开。Gin 的 `c.Request.Context()` 和 GORM 的 `WithContext(ctx)` 都遵循这个惯例。

---

### 3.9.4 避免布尔参数

```go
func CreateUser(name string, isAdmin bool) error
```

调用时：

```go
CreateUser("张三", true) // true 是什么意思？
```

可读性差。可以拆成两个函数：

```go
func CreateUser(name string) error
func CreateAdmin(name string) error
```

或者用选项：

```go
CreateUser("张三", WithAdmin())
```

---

### 3.9.5 Functional Options 模式

参数很多、大部分可选时，用函数选项：

```go
type Server struct {
    Port    int
    Timeout time.Duration
}

type Option func(*Server)

func WithPort(port int) Option {
    return func(s *Server) {
        s.Port = port
    }
}

func WithTimeout(timeout time.Duration) Option {
    return func(s *Server) {
        s.Timeout = timeout
    }
}

func NewServer(opts ...Option) *Server {
    s := &Server{
        Port:    8080,
        Timeout: 30 * time.Second,
    }
    for _, opt := range opts {
        opt(s)
    }
    return s
}
```

使用：

```go
s := NewServer(WithPort(9090), WithTimeout(10*time.Second))
```

这个模式综合了：

- 可变参数；
- 函数类型；
- 闭包；
- 默认值。

Gin/GORM 的很多配置也采用类似思路。

## 3.10 与 Gin/GORM 的关联

### 3.10.1 Gin 的 Handler 就是一个函数

```go
func(c *gin.Context) {
    c.JSON(200, gin.H{"message": "pong"})
}
```

`gin.HandlerFunc` 的定义就是：

```go
type HandlerFunc func(*Context)
```

所以路由注册本质上是在保存函数。

---

### 3.10.2 Gin 中间件返回一个函数

```go
func Timing() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()

        c.Next() // 执行后续 handler

        fmt.Println("耗时：", time.Since(start))
    }
}
```

这是典型的「函数返回函数」+ 闭包。

使用：

```go
r := gin.New()
r.Use(Timing())
```

---

### 3.10.3 Gin 的 Recovery 中间件

Gin 的 `gin.Recovery()` 内部大致做了：

```go
defer func() {
    if err := recover(); err != nil {
        // 记录日志
        c.AbortWithStatus(http.StatusInternalServerError)
    }
}()
```

这正是本章 `defer + recover` 的应用：一个请求的 handler panic 了，服务器不崩溃，返回 500。

---

### 3.10.4 GORM 事务使用闭包

```go
err := db.Transaction(func(tx *gorm.DB) error {
    if err := tx.Create(&user).Error; err != nil {
        return err
    }

    if err := tx.Create(&order).Error; err != nil {
        return err
    }

    return nil
})
```

- `Transaction` 接收一个函数；
- 函数返回 `error`；
- 返回 `nil` 提交事务，返回 `error` 回滚。

这是「函数作为参数 + 错误返回值」的组合。

---

### 3.10.5 GORM 的钩子是方法

```go
func (u *User) BeforeCreate(tx *gorm.DB) error {
    if u.Name == "" {
        return fmt.Errorf("name is required")
    }
    return nil
}
```

方法在第 05 章讲。这里先知道：GORM 会在创建前调用这个方法。

## 3.11 常见错误与陷阱

### 3.11.1 错误速查表

| 错误/现象 | 原因 | 修复 |
|-----------|------|------|
| `if 1 {}` 编译失败 | 条件必须是 bool | 写成比较表达式 |
| `for` 忘记退出条件 | 无限循环 | 加 `break`/`return` |
| range 修改变量无效 | `v` 是副本 | 用索引修改 |
| map 遍历顺序每次不同 | Go 故意随机化 | 需要顺序时先排序 key |
| 闭包输出全是最后一个值 | Go 1.21 及以下的循环变量复用 | 升级到 go 1.22+ 或复制变量 |
| `defer` 在循环里堆积 | 函数结束才执行 | 抽成独立函数 |
| `defer` 打印的是旧值 | 参数在 defer 处求值 | 用闭包读取最新值 |
| `recover()` 返回 nil | 不在 defer 中直接调用 | 放到 defer 函数里 |
| 主 goroutine 捕获不到子 goroutine panic | recover 只对同 goroutine 有效 | 每个 goroutine 自己 recover |
| `fallthrough` 报错 | 用在最后一个 case 或 type switch | 调整位置 |
| `break` 没跳出循环 | switch 里的 break 只跳 switch | 用标签 |
| 函数重载编译失败 | Go 不支持重载 | 改函数名或参数结构 |
| 默认参数编译失败 | Go 不支持默认参数 | 用可变参数/选项 |
| 函数内声明命名函数失败 | Go 不支持嵌套命名函数 | 用函数字面量 |

---

### 3.11.2 `recover` 必须在 `defer` 中直接调用

```go
func bad() {
    recover() // 无效，返回 nil
}

func good() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println(r)
        }
    }()
    panic("boom")
}
```

---

### 3.11.3 `defer` 参数求值时机

```go
x := 1
defer fmt.Println(x) // 记录 1
x = 2
```

不要误以为 `defer` 打印的是 2。

---

### 3.11.4 命名返回值 + defer 会改变结果

```go
func f() (n int) {
    defer func() { n++ }()
    return 1
}
```

返回 2，不是 1。理解这一点，才能看懂 Gin/GORM 源码里的一些写法。

---

### 3.11.5 循环里的闭包

```go
var funcs []func()

for i := 0; i < 3; i++ {
    funcs = append(funcs, func() {
        fmt.Println(i)
    })
}
```

如果模块的 `go.mod` 是 `go 1.21`，三个闭包都会打印 3。解决方式：

- 升级到 go 1.22+；
- 或者在循环内复制变量：

```go
for i := 0; i < 3; i++ {
    i := i // 旧版本的经典写法
    funcs = append(funcs, func() {
        fmt.Println(i)
    })
}
```

## 3.14 本章小结

| 概念 | 一句话解释 | 易错点 |
|------|------------|--------|
| `if` | 条件分支 | 条件必须是 bool |
| `for` | 唯一的循环 | 没有 while |
| `range` | 遍历 | 值是副本；map 顺序随机 |
| 标签 | `break outer` / `continue outer` | 跳出多层循环时用 |
| `switch` | 多分支 | 不需要 break；`fallthrough` 有限制 |
| 多返回值 | 常见 `(结果, error)` | error 放最后 |
| 命名返回值 | 在签名里给返回值命名 | 裸返回慎用 |
| 可变参数 | `...T` | 必须是最后一个参数 |
| 闭包 | 捕获外部变量的函数 | 捕获的是变量本身 |
| `defer` | 函数返回前执行 | LIFO；参数立即求值 |
| `panic` | 中断执行 | 不能跨 goroutine recover |
| `recover` | 捕获 panic | 必须在 defer 中直接调用 |
| 值传递 | 参数都是拷贝 | slice/map 有引用语义 |

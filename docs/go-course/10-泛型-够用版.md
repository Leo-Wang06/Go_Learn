## 10.1 为什么需要泛型：从 TS 说起

### 10.1.1 没有泛型时的重复

对 `[]int`、`[]int64`、`[]float64` 求和，逻辑一样，只能复制三份：

```go
func SumInts(nums []int) int             { /* 同样逻辑 */ }
func SumInt64s(nums []int64) int64       { /* 同样逻辑 */ }
func SumFloat64s(nums []float64) float64 { /* 同样逻辑 */ }
```

如果改用 `[]any`，每个元素都要类型断言，类型检查被推迟到运行期，既啰嗦又不安全。

### 10.1.2 TS 泛型回顾

```ts
function identity<T>(x: T): T {
  return x
}
```

TS 泛型的核心：**类型也是参数**，调用处仍然有类型检查。

### 10.1.3 Go 泛型与对照

```go
func Identity[T any](x T) T {
    return x
}

fmt.Println(Identity(42))      // 42
fmt.Println(Identity("hello")) // hello
```

| 部分 | 示例 | 含义 |
|------|------|------|
| 类型参数列表 | `[T any]` | 声明类型参数 T，约束为 any |
| 类型参数使用 | `x T`、`[]T`、`map[K]V` | 在参数、返回值、函数体中使用 |
| 类型实参 | `Identity[int](42)` | 调用时指定具体类型，通常可省略 |

| TypeScript | Go |
|------------|-----|
| `function f<T>(x: T): T` | `func F[T any](x T) T` |
| `<T extends string \| number>` | `[T string \| int]` 或约束接口 |
| `T[]` | `[]T` |
| `Record<K, V>` | `map[K]V` |
| `class Box<T>` | `type Box[T any] struct` |
| 类型通常可推断 | 可推断，但**不能从返回值推断** |

### 10.1.4 能力边界

能做的：通用算法、通用容器、标准库泛型 API、避免 `any` + 断言。

不能做的：方法不能额外声明类型参数；不能对 `T` 直接做 `type switch`；不能对任意 `T` 使用 `+`、`<`，除非约束允许；`[]int` 不能当 `[]any` 用；泛型不能替代接口的运行时多态。

> 泛型解决「同一套代码，编译期适配多种类型」；接口解决「同一套调用，运行时适配多种实现」。

## 10.2 类型参数

### 10.2.1 基本语法

```go
func PrintTwice[T any](v T) {
    fmt.Println(v)
    fmt.Println(v)
}

func main() {
    PrintTwice("go")
    PrintTwice(42)
}
```

输出为 `go`、`go`、`42`、`42`，每行一个。

签名里 `[T any]` 是类型参数，`(v T)` 是普通参数：名字 `v`，类型 `T`。

类型参数名是惯例，不是语法：`T`（Type）、`K`/`V`（Key/Value）、`E`（Element）、`S`（Slice）、`U`/`A`（第二个类型/累积类型）。读标准库时认识这些名字能加快理解。

### 10.2.2 调用与显式实例化

编译器通常能从实参推断：

```go
PrintTwice("go") // T = string
PrintTwice(42)   // T = int
```

也可以显式指定，常用于推断不出来或想强制类型：

```go
PrintTwice[string]("go")
PrintTwice[int](42)
```

### 10.2.3 `T any` 不等于「T 是 any」

`T any` 表示 T 可以是任意类型，但在函数体里 T 仍是一个未知的具体类型：

```go
func Bad[T any](a, b T) T {
    return a + b // 编译错误：operator + not defined on T
}
```

想让 `+` 可用，必须在约束里列出支持它的类型：

```go
func Add[T int | int64 | float64](a, b T) T {
    return a + b
}
```

### 10.2.4 零值不能写 nil

```go
func Zero[T any]() T {
    return nil // 编译错误：cannot use nil as T value
}
```

正确写法：

```go
func Zero[T any]() T {
    var zero T
    return zero
}
```

调用时必须显式指定类型，因为没有参数可供推断：

```go
fmt.Println(Zero[int]())    // 0
fmt.Println(Zero[string]()) // 空行
fmt.Println(Zero[*int]())   // <nil>
```

## 10.3 类型约束

约束规定「类型参数可以是什么类型」，是泛型安全性的来源。

### 10.3.1 `any`

```go
func First[T any](items []T) (T, bool) {
    if len(items) == 0 {
        var zero T
        return zero, false
    }
    return items[0], true
}
```

`any` 是 `interface{}` 的别名。函数体只能做与具体类型无关的操作：赋值、传参、返回、取地址等。

### 10.3.2 `comparable`

表示类型支持 `==` 和 `!=`：

```go
func IndexOf[T comparable](items []T, target T) int {
    for i, item := range items {
        if item == target {
            return i
        }
    }
    return -1
}

fmt.Println(IndexOf([]string{"go", "ts", "js"}, "ts")) // 1
fmt.Println(IndexOf([]int{10, 20, 30}, 99))            // -1
```

| 类型 | comparable |
|------|------------|
| 布尔、数值、字符串 | 是 |
| 指针、channel | 是 |
| 接口 | 是（两个接口值比较可能 panic） |
| 元素可比较的数组 | 是 |
| 字段都可比较的结构体 | 是 |
| 切片、map、函数 | **否**（只能与 nil 比较） |

所以 `IndexOf([][]int{{1}, {2}}, []int{2})` 编译失败。按内容比较切片要用 `slices.Equal`。

### 10.3.3 联合类型

```go
func Max[T int | int64 | float64](a, b T) T {
    if a > b {
        return a
    }
    return b
}

fmt.Println(Max(3, 9))        // 9
fmt.Println(Max(3.5, 2.5))    // 3.5
fmt.Println(Max[int64](7, 2)) // 7
```

规则：

- 列出的每个类型都必须支持函数体里用到的操作（这里是 `>`）；
- 联合项不能重叠，例如 `int | ~int` 非法；
- 联合类型只能出现在约束接口里，不能当普通参数类型。

可以把约束命名，避免重复：`type Number interface { ~int | ~int64 | ~float64 }`，然后写 `func Max[T Number](a, b T) T`。

### 10.3.4 底层类型 `~T`

```go
type UserID int

func Max[T int | int64](a, b T) T { ... }

var a, b UserID = 1, 2
// Max(a, b) // 编译错误：UserID does not satisfy int | int64
```

`UserID` 的底层类型是 `int`，但它是新类型，不是 `int`（第 02 章）。加 `~` 表示「底层类型是」：

```go
func Max[T ~int | ~int64 | ~float64](a, b T) T { /* 同前 */ }

type Celsius float64

var c1, c2 Celsius = 36.5, 38.0
fmt.Println(Max(c1, c2)) // 38
```

| 约束 | 接受 `float64` | 接受 `type Celsius float64` |
|------|----------------|-----------------------------|
| `float64` | 是 | 否 |
| `~float64` | 是 | 是 |

业务里的 ID、状态码常是自定义类型；写通用函数时若希望兼容它们，记得加 `~`。

### 10.3.5 接口约束：要求方法

```go
type Stringer interface {
    String() string
}

func Join[T Stringer](items []T, sep string) string {
    parts := make([]string, 0, len(items))
    for _, item := range items {
        parts = append(parts, item.String())
    }
    return strings.Join(parts, sep)
}

type Person struct{ Name string }

func (p Person) String() string { return p.Name }

fmt.Println(Join([]Person{{"张三"}, {"李四"}}, ", ")) // 张三, 李四
```

方法接收者规则与普通接口一致：若 `String()` 定义在 `*Person` 上，则只有 `*Person` 满足 `Stringer`，应传 `[]*Person`。

### 10.3.6 约束接口不能当普通类型

```go
type Number interface { ~int | ~float64 }
var n Number // 编译错误：cannot use type Number outside a type constraint
```

`Number` 的类型集合有多个具体类型，编译器无法确定变量大小。它只能用于类型参数。运行时需要装任意值就用 `any`，需要区分类型就用断言或 `type switch`。

### 10.3.7 常用约束速查

`any`（任意）、`comparable`（可比较）、联合类型、`~T`（底层类型）、方法接口、`cmp.Ordered`（可排序）。选择原则：约束按函数体需要写，宁可精确，不要一律 `any`。

## 10.4 泛型类型

### 10.4.1 定义 `Stack[T]`

```go
package main

import "fmt"

type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }


func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 {
        return zero, false
    }
    v := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return v, true
}

func (s *Stack[T]) Len() int { return len(s.items) }

func main() {
    s := &Stack[int]{}
    s.Push(1)
    s.Push(2)
    v, ok := s.Pop()
    fmt.Println(v, ok, s.Len()) // 2 true 1
}
```

要点：

- 方法接收者写 `*Stack[T]`，不能写 `*Stack`；
- 使用时要提供类型实参：`&Stack[int]{}`；
- `Stack[int]` 与 `Stack[string]` 是不同类型，不能互相赋值；
- `nil` 切片可以 `append`，零值栈可以直接用。

需要预分配容量时写构造函数：

```go
func NewStack[T any](capacity int) *Stack[T] {
    return &Stack[T]{items: make([]T, 0, capacity)}
}
```

调用 `NewStack[string](10)`：`[string]` 给类型，`(10)` 给函数。`T` 无法从 `capacity` 推断，必须显式写。

### 10.4.2 方法不能新增类型参数

TS 的类方法可以有自己的泛型：

```ts
class Box<T> {
  map<U>(fn: (value: T) => U): Box<U> { /* ... */ }
}
```

Go **不允许**：

```go
type Box[T any] struct{ value T }

// 编译错误：methods cannot have type parameters
func (b Box[T]) Convert[U any](fn func(T) U) Box[U] {
    return Box[U]{value: fn(b.value)}
}
```

方法可以使用类型本身的 `T`，但不能新增 `U`：

```go
func (b Box[T]) Get() T { return b.value }

func (b Box[T]) MapT(fn func(T) T) Box[T] {
    return Box[T]{value: fn(b.value)}
}
```

需要新类型参数时，改为普通泛型函数：

```go
func Convert[T, U any](b Box[T], fn func(T) U) Box[U] {
    return Box[U]{value: fn(b.value)}
}

b := Box[int]{value: 42}
s := Convert(b, func(n int) string {
    return fmt.Sprintf("数字：%d", n)
})
fmt.Println(s.Get()) // 数字：42
```

> 原因：方法集必须能静态确定，方法级类型参数会让接口匹配和推断复杂化。

### 10.4.3 泛型类型的可比较性

是否可比较取决于字段：`Pair[int, string]` 可比较；`Pair[int, []string]` 含切片，不可比较。编译器按实例化后的具体类型判断。

## 10.5 类型推断

### 10.5.1 从实参推断

`Identity(42)` 推出 `T = int`，`Identity("hello")` 推出 `T = string`，`Identity([]int{1})` 推出 `T = []int`。

### 10.5.2 从函数参数推断

```go
func Map[T, U any](items []T, fn func(T) U) []U {
    out := make([]U, 0, len(items))
    for _, item := range items {
        out = append(out, fn(item))
    }
    return out
}

nums := []int{1, 2, 3}
strs := Map(nums, func(n int) string {
    return fmt.Sprintf("#%d", n)
})
fmt.Println(strs) // [#1 #2 #3]
```

`nums` 是 `[]int`，推出 `T = int`；函数返回 `string`，推出 `U = string`。

### 10.5.3 不能从返回值推断

Go 只看函数实参，不看结果赋给谁：

```go
func NewSlice[T any]() []T {
    return []T{}
}

// s := NewSlice() // 编译错误：cannot infer T
s := NewSlice[string]() // 正确
```

这也是 GORM 必须写 `gorm.G[User](db)` 的原因：`User` 只出现在返回值上。

### 10.5.4 不支持部分推断

类型实参要么全部省略，要么全部写出：

```go
func PairOf[T, U any](a T, b U) (T, U) { return a, b }

PairOf(1, "a")               // 正确，全部推断
PairOf[int, string](1, "a")  // 正确，全部显式
// PairOf[int](1, "a")       // 编译错误：got 1 type argument but 2 type parameters
```

## 10.6 教学示例：Map / Filter / Reduce

### 10.6.1 `Map`：一对一转换

```go
func Map[T, U any](items []T, fn func(T) U) []U {
    out := make([]U, 0, len(items))
    for _, item := range items {
        out = append(out, fn(item))
    }
    return out
}

nums := []int{1, 2, 3, 4}
squares := Map(nums, func(n int) int { return n * n })
fmt.Println(squares) // [1 4 9 16]

names := Map(nums, func(n int) string {
    return fmt.Sprintf("用户%d", n)
})
fmt.Println(names) // [用户1 用户2 用户3 用户4]
```

TS 的 `map` 是数组方法；Go 的 `Map` 是普通函数，因为不能在切片上定义方法（切片不是本地定义的类型）。

### 10.6.2 `Filter`：按条件保留

```go
func Filter[T any](items []T, keep func(T) bool) []T {
    out := make([]T, 0, len(items))
    for _, item := range items {
        if keep(item) {
            out = append(out, item)
        }
    }
    return out
}

type User struct {
    Name string
    Age  int
}

users := []User{{"张三", 17}, {"李四", 22}, {"王五", 16}}
adults := Filter(users, func(u User) bool { return u.Age >= 18 })
fmt.Println(adults) // [{李四 22}]
```

返回新切片，不修改原切片；容量预分配为 `len(items)`，避免多次扩容。

### 10.6.3 `Reduce`：累积成一个值

```go
func Reduce[T, A any](items []T, init A, fn func(A, T) A) A {
    acc := init
    for _, item := range items {
        acc = fn(acc, item)
    }
    return acc
}

nums := []int{1, 2, 3, 4, 5}
sum := Reduce(nums, 0, func(acc, n int) int { return acc + n })
fmt.Println(sum) // 15

joined := Reduce([]string{"go", "ts", "js"}, "", func(acc, s string) string {
    if acc == "" {
        return s
    }
    return acc + ", " + s
})
fmt.Println(joined) // go, ts, js
```

`T` 是元素类型，`A` 是累积类型，两者可以不同。例如 `Reduce([]int{2, 3, 2}, map[int]bool{}, ...)` 可以把整数累积成「已出现集合」。

### 10.6.4 和标准库的关系

标准库没有这三个函数。业务里优先用 `slices`/`maps` 或直接写 `for` 循环，后者通常更直白、更好调试。这三个例子主要用于练习泛型写法。

## 10.7 标准库泛型 API：`slices`

`slices` 从 Go 1.21 起提供，是操作切片的首选工具。

### 10.7.1 排序

以下片段省略 `package`/`import`（需要 `cmp`、`fmt`、`slices`）：

```go
type User struct {
    Name string
    Age  int
}

nums := []int{3, 1, 2}
slices.Sort(nums)
fmt.Println(nums) // [1 2 3]

names := []string{"go", "ts", "js"}
slices.Sort(names)
fmt.Println(names) // [go js ts]

users := []User{{"张三", 28}, {"李四", 22}}
slices.SortFunc(users, func(a, b User) int {
    return cmp.Compare(a.Age, b.Age)
})
fmt.Println(users) // [{李四 22} {张三 28}]
```

- `slices.Sort` 要求元素满足 `cmp.Ordered`（支持 `<`）；
- `slices.SortFunc` 的比较函数返回负数 / 0 / 正数；
- 两者都是**原地排序**，不返回新切片。
- TS 的 `sort` 默认按字符串排序；Go 的数字排序直接按大小。

### 10.7.2 查找

```go
nums := []int{1, 2, 3, 4}

fmt.Println(slices.Contains(nums, 3)) // true
fmt.Println(slices.Contains(nums, 9)) // false
fmt.Println(slices.Index(nums, 3))    // 2
fmt.Println(slices.Index(nums, 9))    // -1

idx := slices.IndexFunc(nums, func(n int) bool { return n > 2 })
fmt.Println(idx) // 2
```

签名：

```go
func Contains[S ~[]E, E comparable](s S, v E) bool
func Index[S ~[]E, E comparable](s S, v E) int
```

`S ~[]E` 表示 S 是任意底层为 `[]E` 的切片类型；`E comparable` 因为内部用 `==`；找不到返回 `-1`。

### 10.7.3 插入与删除

```go
nums := []int{1, 2, 3}

nums = slices.Insert(nums, 1, 9)
fmt.Println(nums) // [1 9 2 3]

nums = slices.Delete(nums, 1, 2) // 删除 [1, 2)
fmt.Println(nums) // [1 2 3]
```

```go
func Insert[S ~[]E, E any](s S, i int, v ...E) S
func Delete[S ~[]E, E any](s S, i, j int) S
```

关键点：

- 返回新的切片头，**必须接住返回值**；
- 可能修改底层数组；
- `Delete(s, i, j)` 删除 `[i, j)`，左闭右开；越界会 panic。

`slices.Insert(nums, 1, 9)` 丢弃返回值不会改变 `nums`，和 `append` 必须接返回值同理。

### 10.7.4 克隆、比较、反转

```go
a := []int{1, 2, 3}
b := slices.Clone(a)

fmt.Println(slices.Equal(a, b)) // true

b[0] = 99
fmt.Println(a) // [1 2 3]
fmt.Println(b) // [99 2 3]

slices.Reverse(a)
fmt.Println(a) // [3 2 1]
```

- `Clone` 创建新底层数组，修改副本不影响原切片；`Clone(nil)` 返回 `nil`；
- `Equal` 按元素比较，要求 `comparable`；
- `Reverse` 原地反转，不返回新切片。

`Clone` 常用于保护内部状态：

```go
func (s *Store) Items() []string {
    return slices.Clone(s.items)
}
```

### 10.7.5 读懂泛型签名

以 `Sort` 为例：

```go
func Sort[S ~[]E, E cmp.Ordered](x S)
```

`[S ~[]E, E cmp.Ordered]` 声明两个类型参数；`S ~[]E` 表示 S 是任意底层为 `[]E` 的切片类型；`E cmp.Ordered` 表示元素支持比较运算符；函数原地排序，无返回值。

为什么用 `S ~[]E` 而不是 `[]E`？为了支持命名切片类型：

```go
type IntList []int

var list IntList = []int{3, 1, 2}
slices.Sort(list) // S = IntList，E = int
```

若签名是 `func Sort[E cmp.Ordered](x []E)`，`IntList` 不能直接传入（切片不协变）。

再看 `Clone`：

```go
func Clone[S ~[]E, E any](s S) S
```

返回类型是 `S`，所以 `Clone(IntList)` 返回 `IntList`，保留命名类型。这种「用 `S ~[]E` 保留原切片类型」是标准库泛型 API 的常见模式。

## 10.8 标准库泛型 API：`maps`

`maps` 从 Go 1.21 起提供。

### 10.8.1 `Clone`、`Copy`、`Equal`

以下片段省略 `package`/`import`，放在 `main` 中即可运行：

```go
m := map[string]int{"a": 1, "b": 2}

m2 := maps.Clone(m)
fmt.Println(maps.Equal(m, m2)) // true

m2["c"] = 3
fmt.Println(len(m), len(m2)) // 2 3

dst := map[string]int{"x": 100}
maps.Copy(dst, m)
fmt.Println(dst) // map[a:1 b:2 x:100]

fmt.Println(maps.Equal(m, map[string]int{"a": 1, "b": 2})) // true
```

- `maps.Clone(nil)` 返回 `nil`；
- `Copy` 把 src 覆盖到 dst，保留 dst 原有的其他键；
- `Equal` 要求键和值都 `comparable`；
- 打印顺序由 `fmt` 排序，但遍历顺序仍然随机。

```go
func Clone[M ~map[K]V, K comparable, V any](m M) M
func Copy[M1 ~map[K]V, M2 ~map[K]V, K comparable, V any](dst M1, src M2)
func Equal[M1, M2 ~map[K]V, K, V comparable](m1 M1, m2 M2) bool
```

`M ~map[K]V` 同样保留命名 map 类型：`maps.Clone(ScoreMap{...})` 返回的仍是 `ScoreMap`，而不会退化成 `map[string]int`。

### 10.8.2 `DeleteFunc` 与 `EqualFunc`

```go
m := map[string]int{"a": 1, "b": 2, "c": 3}
maps.DeleteFunc(m, func(k string, v int) bool { return v < 2 })
fmt.Println(m) // map[b:2 c:3]
```

值不可比较时（例如值是切片），用 `EqualFunc`：

```go
s1 := map[string][]int{"a": {1, 2}}
s2 := map[string][]int{"a": {1, 2}}

ok := maps.EqualFunc(s1, s2, func(a, b []int) bool {
    return slices.Equal(a, b)
})
fmt.Println(ok) // true
```

### 10.8.3 `Keys`、`Values` 与版本差异

**Go 1.23 起**，`maps.Keys`/`Values` 返回迭代器 `iter.Seq`（`iter.Seq[K]` / `iter.Seq[V]`），不是切片。配合 `slices.Sorted` / `slices.Collect` 使用：

```go
m := map[string]int{"b": 2, "a": 1, "c": 3}

fmt.Println(slices.Sorted(maps.Keys(m)))   // [a b c]
fmt.Println(slices.Sorted(maps.Values(m))) // [1 2 3]
fmt.Println(len(slices.Collect(maps.Keys(m)))) // 3
```

这段代码需要 **Go 1.23+**（`range over func` 与 `iter.Seq` 是 1.23 的特性）。

**Go 1.22 没有 `maps.Keys`/`Values`。** 锁定 1.22 时手写：

```go
func Keys[K comparable, V any](m map[K]V) []K {
    keys := make([]K, 0, len(m))
    for k := range m {
        keys = append(keys, k)
    }
    return keys
}

keys := Keys(m)
sort.Strings(keys)
fmt.Println(keys) // [a b c]
```

> 读文档时看 pkg.go.dev 的「added in go1.23」。只需要遍历时，直接 `for k, v := range m` 最简单，也不受版本影响。

## 10.9 如何读 Gin/GORM 中的泛型签名

### 10.9.1 三步法

看到：

```go
func SortFunc[S ~[]E, E any](x S, cmp func(a, b E) int)
```

1. 方括号里是类型参数：`S`、`E`；
2. 各自的约束：`S ~[]E`，`E any`；
3. 参数和返回值如何用：`x S`，比较函数接收两个 `E`，无返回值。

调用 `slices.SortFunc(users, func(a, b User) int {...})` 时，`S = []User`，`E = User`。

### 10.9.2 常见签名片段

看到 `[E comparable]` 就是支持 `==`；`[E cmp.Ordered]` 是支持 `<` 等比较；`[S ~[]E]` 是切片；`[M ~map[K]V]` 是 map；`[T fmt.Stringer]` 是要求 `String() string`。

### 10.9.3 GORM 的 `gorm.G[T]`

GORM v1.30.0 起提供泛型 API：

```go
user, err := gorm.G[User](db).Where("id = ?", 1).First(ctx)
if err != nil {
    return err
}

users, err := gorm.G[User](db).
    Where("age >= ?", 18).
    Order("id DESC").
    Find(ctx)
```

和传统 API 相比：传统写法 `db.Where(...).First(&user)` 返回 `*gorm.DB`，错误在 `.Error`；泛型写法 `gorm.G[User](db).First(ctx)` 直接返回 `(User, error)`，不需要预先声明变量，也不需要 `WithContext`。

读法：

1. `G` 是泛型函数，`[User]` 是显式类型实参；
2. 不能省略 `[User]`，因为类型只出现在返回值上，Go 不会从返回值推断；
3. `First(ctx)` 返回 `(User, error)`，不再检查 `result.Error`；
4. 链式调用仍然成立，只是对象已经绑定 `User` 类型。

注意版本：GORM 泛型 API 是 v1.30.0+ 才有的；传统 API 仍是主流，两者可以混用。读旧文档时不要把泛型签名套上去。

### 10.9.4 Gin 核心 API 中的泛型

Gin v1.9–v1.10 的核心 API 基本没有泛型。`gin.H` 是 `map[string]any`，`HandlerFunc` 是普通函数类型，`Context` 是普通结构体。

泛型更常出现在业务封装里，例如统一绑定 JSON：

```go
func BindJSON[T any](c *gin.Context) (T, error) {
    var req T
    if err := c.ShouldBindJSON(&req); err != nil {
        var zero T
        return zero, err
    }
    return req, nil
}

type CreateUserReq struct {
    Name string `json:"name" binding:"required"`
    Age  int    `json:"age" binding:"gte=0"`
}

// 使用：req, err := BindJSON[CreateUserReq](c)
```

这里 `T` 通常是结构体值类型。不要写 `BindJSON[*CreateUserReq]`：`var req` 是 nil 指针，`&req` 是 `**CreateUserReq`，绑定行为不符合预期。

## 10.10 何时不用泛型

- **只有一两种具体类型**：两个小函数往往比一个泛型函数更清楚；重复两次可以接受，过早抽象增加理解成本。
- **不同类型行为不一样**：泛型函数体对所有 `T` 是同一套代码；`int` 与 `string` 要分别处理时，用接口或 `type switch`。
- **需要运行时多态**：要替换数据库、缓存、mock 实现时，用接口。不要一上来就写 `Repository[T]`，它会让依赖注入、mock、错误处理都变复杂。
- **依赖运行时类型信息**：按字段名反射赋值、按类型选择编码、任意结构体表单绑定，应该用反射或接口。Gin 的绑定、GORM 的模型映射底层都是反射。

判断标准：逻辑是否真的对多种类型完全相同？类型数量是否足够多？泛型版本是否更容易读？有一个答案是「否」，就先写普通代码。等重复出现第三次，再考虑抽象。

## 10.11 常见错误与陷阱

### 10.11.1 速查表

| 错误/现象 | 原因 | 修复 |
|-----------|------|------|
| `cannot use type Number outside a type constraint` | 把约束接口当普通类型 | 用具体类型或 `any` |
| `operator + not defined on T` | 约束没列出支持 `+` 的类型 | 用 `~int \| ~float64` |
| `cannot infer T` | 类型只出现在返回值 | 显式写 `F[int]()` |
| `got 1 type argument but 2 type parameters` | 不支持部分推断 | 全部写或全部省略 |
| `methods cannot have type parameters` | 方法不能新增类型参数 | 改为泛型函数 |
| `UserID does not satisfy int` | 新类型不是底层类型 | 约束加 `~int` |
| `cannot use []int as []any` | 切片没有协变 | 用泛型函数逐个转换 |

### 10.11.2 约束太宽，函数体用不了运算符

```go
func Sum[T any](nums []T) T {
    var total T
    for _, n := range nums {
        total += n // 编译错误
    }
    return total
}
```

修复：`func Sum[T ~int | ~int64 | ~float64](nums []T) T`。约束按函数体的需要写，不要一律 `any`。

### 10.11.3 其他高频错误

- **忘记 `~`**：`type UserID int` 不满足 `[T int]`，要写 `[T ~int]`。
- **把 `[]int` 当 `[]any` 传**：切片不协变，编译失败；改用泛型函数 `func PrintAll[T any](items []T)`。
- **在方法上声明新类型参数**：`func (s *Stack[T]) Map[U any](...)` 编译失败；改为普通函数 `func MapStack[T, U any](s *Stack[T], ...)`。
- **以为 `T` 有运行时类型信息**：`T any` 不能直接做类型断言或 `type switch`；先转 `any(v)`，但那意味着失去泛型的编译期安全，应重新考虑是否该用泛型。

## 10.12 与 Gin/GORM 的关联

### 10.12.1 业务中的 `slices`/`maps`

排序用 `slices.SortFunc`，判断 ID 是否存在用 `slices.Contains`，删除元素用 `slices.Delete`，复制结果用 `slices.Clone`；配置 map 用 `maps.Clone`、`maps.Copy`、`maps.Equal`。这些是 Gin/GORM 业务代码里处理 `[]User`、`[]Order`、配置项的高频操作。

### 10.12.2 GORM 泛型 API 的读法

```go
gorm.G[User](db).Where("status = ?", "active").Find(ctx)
```

`gorm.G` 是泛型函数，`[User]` 显式绑定模型，`Find(ctx)` 接收 context 并返回 `([]User, error)`。与传统 API 的差别主要是类型安全和错误返回方式；底层 SQL 生成、回调、钩子是同一套。

### 10.12.3 Gin 业务封装的边界

可以抽：统一 JSON 绑定、分页响应 `PageResult[T]`、列表转换。不建议抽：泛型 Handler 注册（Gin 路由签名固定为 `func(*gin.Context)`）、泛型中间件、泛型 Service 基类。业务差异大时，接口更合适。

## 10.15 本章小结

| 概念 | 一句话解释 | 易错点 |
|------|------------|--------|
| 类型参数 | `[T any]` 声明类型占位符 | 不是 `any` 值 |
| `comparable` | 支持 `==`/`!=` | 切片、map、函数不满足 |
| 联合类型 | `int \| int64` | 类型不能重叠 |
| `~T` | 底层类型为 T | 兼容自定义类型 |
| 接口约束 | 要求方法集 | 约束接口不能当值类型 |
| 泛型类型 | `Stack[T]` | 使用时必须写类型实参 |
| 类型推断 | 从实参推断 | 只看参数，不看返回值 |
| `slices`/`maps` | 标准库泛型工具 | 版本差异与返回值 |
| 何时不用 | 逻辑不同、类型少、接口更清晰 | 不要为泛型而泛型 |
